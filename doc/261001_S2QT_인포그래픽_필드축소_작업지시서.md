# 261001 · infographic 필드 축소 + QT 섹션 재활용 — 작업지시서

선행 문서: [검토](261001_S2QT_인포그래픽_필드축소_검토.md) · [파일맵](260922_S2QT_파일맵.md)

## 확정 사항

| # | 내용 | 근거 |
|---|---|---|
| 1 | infographic은 **`follow` / `extra` / `core`** 3개만 생성한다 | 사용자 결정 (검토 6-1 안 A) |
| 2 | `guide` ← summary, `apply` ← reflection, `prayer` ← prayer **QT 섹션에서 조립** | 〃 |
| 3 | md 섹션 제목 **"오늘의 적용" → "깊은 묵상과 적용"** | 선택하신 안의 미리보기. 내용이 QT reflection이 되므로 |
| 4 | **저장된 JSON에 해당 항목이 있으면 그것을, 없으면 QT 섹션에서** 조립한다 | 사용자 결정 (폴백) |
| 5 | `version`은 **"1.1"** 유지 | infographic 객체는 여전히 존재한다 |

> ### 확정 4가 만드는 제약 — 필드를 지우면 안 됩니다
>
> 2026-10-01 이전 이력에는 `infographic.guide/apply/prayer`가 **들어 있습니다.** 폴백을 쓰려면
> **그 값을 읽을 수 있어야** 하므로, `InfographicData`에서 세 필드를 **제거하면 안 됩니다.**
> 프롬프트는 더 이상 생성하지 않지만 구조체에는 **읽기 전용으로 남깁니다**(단계 B-1).
>
> 우선순위는 한 줄입니다 — **저장된 값이 있으면 이긴다.**
>
> | 이력 | guide / apply / prayer 출처 |
> |---|---|
> | 10-01 이전 (6필드) | **저장된 infographic** — 당시 산출물이 그대로 재현됨 |
> | 10-01 이후 (3필드) | **QT 섹션** |
>
> **대가 하나** — 옛 이력을 재작업한 뒤 Step2에서 길잡이·기도를 고쳐도 md에는 반영되지 않습니다.
> 저장된 값이 이기기 때문입니다. 새 이력에서는 반영됩니다. 폴백을 택한 이상 피할 수 없는 결과이며,
> 해당 범위는 10-01 이전 이력으로 **점점 줄어듭니다.**

## 단계 A — 프롬프트

`defaultQTPromptInfographic`([:292-354](../service/prompt_qt_json.go#L292))에서 **5곳**을 고칩니다.
한 곳이라도 빠지면 LLM이 옛 필드를 계속 생성합니다(무해하지만 토큰 낭비이고, 축소 목적이 사라집니다).

- **A-1 용어 고정** — 생성 대상만 남깁니다.
  ```
  용어 고정: 말씀을 따라 / 더하는 말씀 / 말씀의 핵심
  ```
- **A-2 문체** — `guide, prayer` 줄을 지웁니다.
  ```
  문체: follow, extra, core — 평서형 단정 (~한다 / ~이다)
  ```
- **A-3 필드 규칙** — `guide` · `apply` · `prayer` 항목 3개를 지웁니다.
  `guide` 규칙에 있던 *"QT summary(5~6문장)보다 짧게"* 같은 **QT 참조 문구도 함께** 사라집니다.
- **A-4 템플릿**
  ```json
  "infographic": { "follow": ["...","...","..."], "extra": ["...","..."], "core": "..." }
  ```
- **A-5 QUALITY CHECKS** — 3필드 기준으로 줄입니다.
  ```
  ✓ version 이 "1.1" 이다
  ✓ infographic 이 최상위 마지막 필드로 존재한다
  ✓ 3개 필드(follow/extra/core)가 모두 있다
  ✓ follow 는 3~5개, extra 는 0~3개이다
  ✓ follow 가 QT message 문장의 어미만 바꾼 것이 아니다
  ✓ 이 블록 안에 "설교"라는 단어가 없다
  ✓ extra 의 모든 예화가 전사문에 실제로 존재한다
  ```

> **"QT 본문과 독립적으로 다시 쓴다"** 규칙([:298-306](../service/prompt_qt_json.go#L298))은
> **유지합니다.** 남은 3필드에 그대로 적용됩니다.

## 단계 B — 타입과 렌더러

**B-1** `InfographicData`는 **줄이지 않습니다.** 프롬프트에서만 빼고, 구조체에는 읽기 전용으로
남깁니다(확정 4). `omitempty`를 붙여야 새 `temp.json`에 빈 키가 남지 않습니다.

```go
// InfographicData는 LLM이 QT와 별개로 새로 쓰는 부분을 담는다.
type InfographicData struct {
	Follow []string `json:"follow"`
	Extra  []string `json:"extra"`
	Core   string   `json:"core"`

	// 아래 3개는 2026-10-01부터 프롬프트가 생성하지 않는다.
	// 그 이전에 저장된 이력을 재작업할 때 당시 산출물을 재현하려고 읽기만 한다.
	// 새로 채우는 코드는 없어야 한다 — 지우면 옛 이력의 값을 읽을 수 없다.
	Guide  string   `json:"guide,omitempty"`
	Apply  []string `json:"apply,omitempty"`
	Prayer string   `json:"prayer,omitempty"`
}
```

**B-2** QT에서 가져오는 본문을 담을 구조체를 둡니다. **`SermonSummaryMeta`에 섞지 마십시오** —
그쪽은 머리말·꼬리말용이고, 여기는 본문입니다.

```go
// SermonSummaryQT는 sermon_summary.md가 QT 섹션에서 재활용하는 본문이다.
// LLM이 따로 쓰지 않으므로 Step2 편집이 그대로 md에 반영된다.
type SermonSummaryQT struct {
	Guide  string   // sections[summary]  — 말씀의 길잡이
	Apply  []string // sections[reflection] — 깊은 묵상과 적용
	Prayer string   // sections[prayer]   — 오늘의 기도
}
```

**B-3** `ValidateInfographic`에서 guide/prayer/apply 검사를 **제거**합니다. 남는 것은
core 비어있음 · follow 3~5개 · extra 0~3개뿐입니다.

> **구조체에는 남기지만 검증에서는 뺍니다.** 새 JSON에는 없는 것이 정상이므로, 검증에 남기면
> **장년 md 생성이 전부 막힙니다**(검증 실패 → md 0바이트).
>
> `apply` 개수 상수(`infographicApplyMin/Max`)도 함께 지웁니다. 남겨 두면 다음 사람이
> "검증은 있는데 왜 안 쓰지?"를 다시 조사합니다.

**B-4** `RenderInfographicMD(data *InfographicData, qt SermonSummaryQT, meta SermonSummaryMeta) string`

세 인자의 역할이 각각 다릅니다 — **LLM 생성분 / QT 재활용분 / 머리말·꼬리말**.

```go
b.WriteString("## 말씀의 길잡이\n")
b.WriteString(strings.TrimSpace(qt.Guide) + "\n\n")

writeInfographicList(&b, "말씀을 따라", data.Follow)
writeInfographicParagraphs(&b, "더하는 말씀", data.Extra)

b.WriteString("## 말씀의 핵심\n")
b.WriteString(strings.TrimSpace(data.Core) + "\n\n")

writeInfographicList(&b, "깊은 묵상과 적용", qt.Apply)   // 제목 변경

b.WriteString("## 오늘의 기도\n")
b.WriteString(strings.TrimSpace(qt.Prayer) + "\n\n")

writeInfographicInline(&b, "관련 성구", normalizeBibleRefSlice(meta.SupportScriptures))

return strings.TrimRight(b.String(), "\n") + "\n"
```

**B-5** 길잡이·기도도 **비면 섹션째 생략**합니다. 지금까지는 `ValidateInfographic`이 비어 있지
않음을 보장했지만, 이제 QT 섹션에서 오므로 그 보장이 없습니다. 제목만 남는 것을 막습니다.

## 단계 C — 조립과 호출부 3곳

**C-0** 우선순위를 정하는 함수를 **하나만** 둡니다. 호출부 3곳이 각자 폴백을 적어 넣으면
한 곳이 빠졌을 때 **그 경로에서만 옛 이력이 다르게 나옵니다.**

```go
// resolveSermonSummaryQT는 md가 재활용할 본문을 정한다.
//
// 2026-10-01 이전 이력에는 infographic에 guide/apply/prayer가 들어 있다.
// 있으면 그것이 이긴다 — 당시 산출물이 그대로 재현된다.
// 없으면(= 그 이후 JSON) QT 섹션에서 가져온다.
func resolveSermonSummaryQT(data *InfographicData, sections []QTSectionData) SermonSummaryQT {
	out := extractSermonSummaryQT(sections)

	if data == nil {
		return out
	}
	if g := strings.TrimSpace(data.Guide); g != "" {
		out.Guide = g
	}
	if a := cleanStringSlice(data.Apply); len(a) > 0 {
		out.Apply = a
	}
	if p := strings.TrimSpace(data.Prayer); p != "" {
		out.Prayer = p
	}
	return out
}
```

**C-1** 섹션 추출기는 그 아래에 둡니다. `qtstep2_service.go`의 맵·섹션 헬퍼들 옆이 자리입니다.

```go
// extractSermonSummaryQT는 QT 섹션에서 md가 재활용할 본문을 꺼낸다.
// Step1·Step2·재작업이 모두 조립된 QTSectionDoc을 갖고 있으므로 경로는 하나다.
func extractSermonSummaryQT(sections []QTSectionData) SermonSummaryQT {
	var out SermonSummaryQT

	for _, sec := range sections {
		switch strings.TrimSpace(sec.Type) {
		case "summary":
			out.Guide = firstParagraphText(sec.Blocks)
		case "reflection":
			out.Apply = firstListItems(sec.Blocks)
		case "prayer":
			out.Prayer = firstParagraphText(sec.Blocks)
		}
	}
	return out
}
```

> 같은 추출 패턴이 이미 두 군데 있습니다 — [qtstep2_service.go `Load()`](../service/qtstep2_service.go)의
> switch문과 `office_service.go`의 `officeFindSection`/`officeExtractParagraphTexts`.
> **세 번째를 만드는 셈이므로**, `firstParagraphText`/`firstListItems`를 작은 공용 헬퍼로 빼고
> 가능하면 `Load()`도 그것을 쓰게 하십시오.

**C-2 Step1** — `writeSermonSummary`에서 `resolveSermonSummaryQT(doc.Infographic, doc.Sections)`.

> 새 LLM JSON에는 세 필드가 없으므로 사실상 섹션에서 옵니다. 다만 사용자가 **옛 형식 JSON을
> 손으로 붙여넣는** 경우가 있으므로 여기서도 폴백을 거칩니다.

**C-3 재작업** — `restoreInfographicFile`에서 동일. **확정 4가 실제로 작동하는 자리**입니다.
옛 6필드 이력이 당시 산출물 그대로 복원됩니다.

**C-4 Step2** — `rewriteSermonSummary`가 지금은 `metadata`만 받습니다.
**조립이 끝난 `doc QTSectionDoc` 전체를 받도록** 바꾸십시오. 그러면 metadata와 sections를
한 값에서 꺼내고, 세 호출부가 모두 같은 추출기를 씁니다.

```go
s.rewriteSermonSummary(doc)   // doc.Metadata + doc.Sections
```

> **이 단계가 이번 작업의 실질적 이득입니다.** 지금은 Step2에서 길잡이·기도를 고쳐도 md가
> 바뀌지 않습니다(박제된 `metadata.infographic`을 쓰므로). C-4 후에는 자동으로 반영됩니다.

## 함정

1. **단계 A의 5곳 중 하나라도 빠뜨리면** LLM이 옛 필드를 계속 냅니다. 무해해 보이지만
   축소 목적 자체가 사라집니다. 특히 **QUALITY CHECKS**를 잊기 쉽습니다.
2. **C-4를 빠뜨리면** 이번 작업의 가장 큰 이득이 사라집니다. 겉보기에는 정상 동작합니다.
3. **B-5를 빠뜨리면** QT 섹션이 비었을 때 제목만 남습니다. 이전에는 검증이 막아 주던 경우입니다.
4. **`metadata.infographic` 보존**(`preserveInternalMetaFields`)은 **그대로 둡니다.**
   필드가 줄었을 뿐 여전히 Step2 재렌더에 필요합니다.
5. **`InfographicData`에서 guide/apply/prayer를 지우고 싶은 충동을 참으십시오.** 프롬프트가
   생성하지 않으니 죽은 필드처럼 보이지만, 지우면 **옛 이력의 폴백이 조용히 사라집니다**
   (`encoding/json`이 모르는 키를 말없이 버리므로 에러도 나지 않습니다).
6. **폴백은 `resolveSermonSummaryQT` 한 곳에만** 둡니다. 호출부에 흩어 놓으면 한 곳이 빠졌을 때
   그 경로에서만 옛 이력이 다르게 나옵니다.
7. 저장소 전체가 CRLF입니다. **`gofmt -w` 일괄 실행 금지.** 신규 LF 파일만 포맷합니다.
