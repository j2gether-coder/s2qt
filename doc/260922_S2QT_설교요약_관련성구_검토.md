# 260922 · sermon_summary.md에 「관련 성구」 섹션 추가 — 검토

> **READ ONLY 검토서**입니다. 이 문서 작성 시점에 코드는 한 줄도 바꾸지 않았습니다.

## 1. 요청

`sermon_summary.md`의 **오늘의 기도 아래**에 `metadata.support_scriptures`를 한 줄로 덧붙입니다.

```markdown
## 오늘의 기도
아버지 하나님, 성령을 보내 주셔서 감사합니다. …

## 관련 성구
시편 27:8, 요한복음 14:9, 고린도후서 3:18
```

## 2. 결론

**가능하고, 작습니다.** 새 데이터를 만들 필요가 없습니다. `support_scriptures`는 이미
LLM 통합 프롬프트의 출력 필드이고, Step1이 파싱하는 그 문서 안에 들어 있습니다.

다만 **데이터가 들어오는 경로가 기존 4개 인자와 다릅니다.** 이것이 이 작업의 전부입니다.

---

## 3. 데이터가 어디 있나

`RenderInfographicMD`가 지금 받는 값의 출처를 보면 규칙이 하나 있습니다.

| 인자 | 출처 | 성격 |
|---|---|---|
| `data *InfographicData` | `doc.Infographic` | **LLM 출력** |
| `series` | 화면 기본정보 (`req.Series`) | 사람 입력 |
| `title` | 화면 기본정보 (`req.Title`) | 사람 입력 |
| `bibleText` | 화면 기본정보 (`req.BibleText`) | 사람 입력 |

`support_scriptures`는 **둘 중 어느 쪽도 아닙니다.**

- `doc.Infographic` **안에는 없습니다.** `InfographicData`는 `guide/follow/extra/core/apply/prayer` 6개뿐입니다.
- 화면 기본정보에도 **없습니다.** Step1 입력란에 관련 성구는 없습니다.

실제 위치는 `doc.Metadata["support_scriptures"]`입니다 — `QTSectionDoc.Metadata`의
`map[string]any` 안에, LLM이 준 `[]any` 형태로 들어 있습니다.

이 맵은 Step1 저장 시점에 이미 메모리에 있으므로 **`temp.json`을 다시 읽을 필요가 없습니다.**
`getStringSliceFromMap`([qtstep2_service.go:430](../service/qtstep2_service.go#L430))이
`[]any`·`[]string`·쉼표 문자열을 모두 받아 주므로 그대로 씁니다.

## 5. 함정

### 5-1. 0개가 정상입니다 — 검증에 넣으면 안 됩니다

프롬프트가 `support_scriptures`를 **"0-3개"** 로 규정합니다
([prompt_qt_json.go:146](../service/prompt_qt_json.go#L146)). 관련 성구가 없는 설교는 정상입니다.

`ValidateInfographic`에 개수 규칙을 추가하면 **관련 성구 없는 설교의 md 생성이 통째로 막힙니다.**
`writeSermonSummary`가 검증 실패 시 파일을 0바이트로 비우기 때문입니다
([qtstep1_service.go:181](../service/qtstep1_service.go#L181)).

→ **검증에 추가하지 않습니다.** 0개면 `## 더하는 말씀`과 같은 방식으로 **섹션 자체를 생략**합니다.

### 5-2. 마지막 줄 개행

지금 `## 오늘의 기도`는 문서의 **마지막 섹션**이라 `"\n"` 하나로 끝납니다
([infographic_service.go:100](../service/infographic_service.go#L100)).

뒤에 섹션이 붙으려면 `"\n\n"`이어야 하는데, 관련 성구가 0개면 다시 `"\n"` 하나여야 합니다.
분기를 만들지 말고 **기도를 `"\n\n"`로 쓰고 반환 직전에 `TrimRight` 후 `"\n"` 하나를 붙이는** 편이
깔끔합니다. 어느 섹션이 마지막이 되든 결과가 같아집니다.

### 5-3. 성구 표기 정규화

`## 성경본문`은 `normalizeBibleReference`를 거칩니다
([infographic_service.go:84](../service/infographic_service.go#L84)). 관련 성구도 같은 처리를
해야 합니다 — 안 하면 **md만 "살전 1:1"이고 나머지 산출물은 "데살로니가전서 1:1"** 이 됩니다.

다른 산출물은 모두 `normalizeBibleRefSlice`를 씁니다
([qtstep2_service.go:81](../service/qtstep2_service.go#L81),
[extended_service.go:99](../service/extended_service.go#L99)). md도 같은 함수를 씁니다.
이 함수는 정규화·트림·**중복 제거**까지 함께 합니다.

### 5-4. Step2에서 고친 관련 성구는 md에 반영되지 않습니다

`sermon_summary.md`는 **Step1 저장 시점**과 **재작업 복원 시점**에만 쓰입니다.
Step2 저장은 md를 건드리지 않습니다.

관련 성구는 Step2에서 **사용자가 직접 편집하는 필드**입니다
([bindQTStep2.js:156](../frontend/src/components/qt/bindQTStep2.js#L156)).
따라서 Step2에서 성구를 고쳐도 md는 Step1 시점 값 그대로입니다.

> 제목·본문 성구도 이미 같은 상태이므로 **새로 생기는 문제는 아닙니다.** 다만 관련 성구는
> LLM이 비교적 자주 틀리는 필드라 편집 빈도가 높을 수 있습니다. **결정이 필요합니다(7-1).**

### 5-5. 시그니처가 인자 5개가 됩니다

```go
RenderInfographicMD(data, series, title, bibleText, supportScriptures)
```

문자열 3개가 연달아 있어 **호출부에서 순서를 바꿔 넣어도 컴파일이 통과합니다.**
이미 한 번 인자를 늘린 함수이고(9/5 `series` 추가), 이번이 두 번째입니다. **결정이 필요합니다(7-2).**

### 5-6. 구버전 이력은 영향 없습니다

구버전 이력은 `llmDoc == nil`이라 재작업 시 md를 **아예 만들지 않습니다**
([history_service.go:609](../service/history_service.go#L609)). 이번 변경과 무관합니다.

### 5-7. 비장년은 영향 없습니다

md 자체가 장년 전용입니다([qtstep1_service.go:177](../service/qtstep1_service.go#L177)).

## 6. 영향 없음을 확인한 것

- **`temp.json` 스키마** — 읽기만 합니다. 필드를 추가하지 않습니다.
- **DB 스키마** — 변경 없습니다.
- **`ALTER TABLE` 경로 부재** — 해당 없습니다.
- **다른 산출물**(HTML·PDF·PNG·DOCX·PPTX·`extended.html`) — 관련 성구를 이미 각자 렌더합니다.
- **md를 되읽는 코드** — 없습니다. 쓰기 전용 산출물입니다.
- **Wails 바인딩** — 내부 함수 시그니처만 바뀝니다. 재생성 불필요합니다.

## 7. 결정이 필요한 것

### 7-1. Step2 편집을 md에 반영할 것인가

| 안 | 내용 | 비용 |
|---|---|---|
| **A. 현행 유지** | md는 Step1 시점 스냅샷. 제목·본문 성구와 동일한 취급 | 0 |
| **B. Step2 저장 시 md 재생성** | `qtstep2_service.Save()`에서 md를 다시 씀 | +0.3일, 아래 문제 있음 |

**B는 겉보기보다 비쌉니다.** Step2의 `QTStep2Data`에는 `infographic` 객체가 없습니다.
md를 다시 쓰려면 Step2가 인포그래픽 데이터를 어딘가에서 다시 가져와야 하는데, 그 원천은
작업내역 DB뿐입니다. 그리고 md는 **외부 에디터로 손보는 산출물**이라, Step2 저장이 덮어쓰면
사용자가 md에 한 편집이 사라집니다.

→ **A를 권합니다.**

### 7-2. 시그니처를 어떻게 할 것인가

| 안 | 내용 |
|---|---|
| **A. 인자 5개** | 변경 최소. 문자열 3개 연속이라 순서 실수 위험 |
| **B. 파라미터 구조체** | `RenderInfographicMD(data, meta)` — 호출부에서 필드명이 드러남. 테스트 5곳 수정 |

B로 가면 재작업 경로의 폴백 로직([history_service.go:618-633](../service/history_service.go#L618-L633))도
구조체 하나를 채우는 형태로 정리됩니다. 어차피 두 호출부와 테스트 5곳을 모두 여는 작업입니다.

→ **B를 권합니다.** 다음에 필드가 또 늘어도 시그니처가 그대로입니다.
