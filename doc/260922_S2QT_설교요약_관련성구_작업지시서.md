## 확정 2가 만든 새 문제 — 인포그래픽 데이터를 Step2가 어떻게 얻는가

`QTStep2Data`에는 인포그래픽이 없습니다. Step2가 md를 다시 쓰려면 `InfographicData`를
어딘가에서 가져와야 합니다. 세 가지 후보를 검토했습니다.

| 안 | 문제 |
|---|---|
| 작업내역 DB에서 조회 | Step2가 현재 세션의 history ID를 모릅니다. 상태를 새로 들고 다녀야 합니다 |
| 사이드카 파일 (`sermon_summary_data.json`) | **파일 2개를 동기화해야 합니다.** md를 비우는 모든 경로에서 사이드카도 비워야 하고, 빠뜨리면 이전 설교의 인포그래픽이 되살아납니다 |
| **`temp.json`의 `metadata.infographic`** | **없음** (아래) |

### 채택: `metadata.infographic`

**이미 같은 문제를 푼 전례가 이 파일 안에 있습니다.** `support_scriptures_full`은
Step2 UI가 편집하지 않는 내부 전용 필드인데, `preserveInternalBlogFields()`
([qtstep2_service.go:144](../service/qtstep2_service.go#L144))가 이전 `temp.json`에서 복사해
유실을 막고 있습니다. `infographic`도 정확히 같은 성격입니다.

결정적인 이유는 **stale 위험이 구조적으로 없다**는 점입니다. 인포그래픽이 문서와 **같은 파일 안에**
있으므로, Step1이 새 `temp.json`을 쓰면 이전 설교의 인포그래픽도 함께 사라집니다. 사이드카는
비우기를 한 곳이라도 빠뜨리면 조용히 어긋납니다.

> **8/31 확정 사항 3("temp.json에 infographic을 넣지 않는다")과 충돌하지 않습니다.**
> 그 결정의 이유는 *"version 1.0을 유지해 Step2가 지금까지와 똑같이 동작하게 한다"* 였습니다.
> `metadata`는 `map[string]any`라 키가 늘어도 스키마가 바뀌지 않고, Step2 `Load()`는 아는 키만
> 꺼내므로 **version 1.0 그대로, Step2 동작도 그대로**입니다. 이유가 그대로 지켜집니다.

**유효할 때만 저장합니다.** Step1의 md 생성 게이트 2개(장년 · 검증 통과)를 통과했을 때만
`metadata.infographic`을 넣습니다. 그러면 Step2의 규칙이 한 줄로 끝납니다 —
*`metadata.infographic`이 있으면 md를 다시 쓰고, 없으면 md를 건드리지 않는다.*

## 단계 A — 렌더러

**A-1** `types.go`에 파라미터 구조체를 둡니다. 인포그래픽 데이터가 아니라 **문서 겉면(메타)** 을
담으므로 `InfographicData` 옆에 둡니다.

```go
// SermonSummaryMeta는 sermon_summary.md의 머리말과 꼬리말에 들어가는 값이다.
// 인포그래픽 본문(InfographicData)과 달리 이 값들은 LLM 출력이 아니거나,
// 사람이 나중에 고칠 수 있는 값이다.
type SermonSummaryMeta struct {
	Series            string   // 화면 입력. 비면 줄 자체를 생략
	Title             string   // 장년은 화면 입력, 비장년은 LLM 제목
	BibleText         string   // 화면 입력
	SupportScriptures []string // LLM 출력 → Step2에서 편집 가능. 0개가 정상
}
```

**A-2** `RenderInfographicMD(data *InfographicData, meta SermonSummaryMeta) string`로 바꿉니다.

**A-3** `## 오늘의 기도` 뒤에 `## 관련 성구`를 씁니다.

```go
b.WriteString("## 오늘의 기도\n")
b.WriteString(strings.TrimSpace(data.Prayer) + "\n\n")   // "\n" → "\n\n"

writeInfographicInline(&b, "관련 성구", normalizeBibleRefSlice(meta.SupportScriptures))

return strings.TrimRight(b.String(), "\n") + "\n"
```

**A-4** 새 헬퍼를 둡니다. 기존 두 헬퍼(`writeInfographicList` 불릿 / `writeInfographicParagraphs`
문단)와 같은 계약입니다 — **비면 아무것도 쓰지 않습니다.**

```go
// writeInfographicInline은 쉼표로 이어 붙인 한 줄 섹션을 쓴다(관련 성구).
func writeInfographicInline(b *strings.Builder, heading string, items []string) {
	if len(items) == 0 {
		return
	}
	b.WriteString("## " + heading + "\n")
	b.WriteString(strings.Join(items, ", ") + "\n\n")
}
```

> **A-3의 `TrimRight`가 핵심입니다.** 지금은 기도가 마지막이라 `"\n"` 하나로 끝나는데, 관련 성구가
> 붙으면 기도 뒤에 빈 줄이 필요합니다. 분기를 만들지 말고 **모든 섹션이 `"\n\n"`로 끝나게 한 뒤
> 반환 직전에 한 번 정규화**하십시오. 어느 섹션이 마지막이 되든 결과가 같아집니다.

`normalizeBibleRefSlice`는 정규화·트림·**중복 제거**를 함께 합니다. 렌더러 안에서 호출하면
두 호출부가 각자 기억할 필요가 없습니다.

## 단계 B — Step1

**B-1** `writeTempJSON`이 유효한 인포그래픽을 `metadata`에 넣습니다. **게이트를 통과했을 때만** 넣습니다.

```go
func (s *QTStep1Service) writeTempJSON(doc *QTLLMDoc, audience string) error {
	qt := doc.QTSectionDoc
	...
	// 인포그래픽은 Step2가 md를 다시 쓸 때 필요하므로 metadata에 실어 보낸다.
	// Step2 UI는 이 키를 모르며, preserveInternalMetaFields()가 저장 때마다 보존한다.
	// 유효할 때만 넣어야 Step2가 "있으면 쓴다"만으로 끝난다.
	if audience == AudienceAdult && len(ValidateInfographic(doc.Infographic)) == 0 {
		qt.Metadata["infographic"] = doc.Infographic
	}
	...
}
```

> `qt := doc.QTSectionDoc`는 얕은 복사이고 `Metadata`는 맵이라 **같은 맵을 가리킵니다.**
> 즉 `doc.Metadata`에도 `infographic` 키가 생깁니다. 작업내역 DB에 저장되는 JSON에도 들어가지만,
> 그 JSON은 어차피 `infographic` 최상위 필드를 이미 담고 있으므로 재작업에 영향이 없습니다.
> 신경 쓰인다면 `qt.Metadata`를 얕게 복사한 뒤 키를 넣으십시오. **`saveHistory`가 `writeTempJSON`
> 뒤에 실행된다는 순서 의존이 생기므로**, 복사하는 편을 권합니다.

**B-2** `writeSermonSummary` 호출부를 구조체로 바꿉니다.


## 단계 D — Step2 저장 시 md 재생성

**D-1** `preserveInternalBlogFields`를 `preserveInternalMetaFields`로 넓히고 `infographic`을
보존 목록에 넣습니다. 이름도 `blog`가 아니게 바꿉니다(`extended.html` 개명과 일관).

```go
if v, ok := prev.Metadata["infographic"]; ok && v != nil {
	metadata["infographic"] = v
}
```

**D-2** `Save()`가 `temp.json`을 쓴 **뒤에** md를 다시 씁니다. temp.json 저장이 실패하면 md를
건드리지 않아야 합니다.

```go
// Step2에서 고친 관련 성구·제목·시리즈를 sermon_summary.md에도 반영한다.
// metadata.infographic이 없으면(비장년이거나 Step1 검증 실패) 파일을 건드리지 않는다.
s.rewriteSermonSummary(doc.Metadata)
```

**D-3** `rewriteSermonSummary`를 새로 둡니다. **실패해도 저장 자체를 되돌리지 않습니다** —
temp.json과 temp.html은 이미 정상이고, md는 부수 산출물입니다.

```go
func (s *QTStep2Service) rewriteSermonSummary(metadata map[string]any) {
	data := getInfographicFromMap(metadata, "infographic")
	if data == nil {
		return
	}

	content := RenderInfographicMD(data, SermonSummaryMeta{
		Series:            getStringFromMap(metadata, "series"),
		Title:             getStringFromMap(metadata, "title"),
		BibleText:         getStringFromMap(metadata, "bible_text"),
		SupportScriptures: getStringSliceFromMap(metadata, "support_scriptures"),
	})

	if err := os.WriteFile(s.Paths.TempSermonSummary, []byte(content), 0o644); err != nil {
		LogError("step2: sermon_summary.md 갱신 실패: " + err.Error())
		return
	}
	LogInfo("step2: sermon_summary.md 갱신 완료")
}
```

**D-4** `getInfographicFromMap`을 둡니다. 맵에는 `*InfographicData`(Step2 저장 직후)일 수도,
`map[string]any`(파일에서 읽은 뒤)일 수도 있으므로 **재마샬로 통일**합니다.

```go
func getInfographicFromMap(m map[string]any, key string) *InfographicData {
	if m == nil || m[key] == nil {
		return nil
	}
	b, err := json.Marshal(m[key])
	if err != nil {
		return nil
	}
	var out InfographicData
	if err := json.Unmarshal(b, &out); err != nil {
		return nil
	}
	return &out
}
```

## 함정

1. **단계 C-2를 빠뜨리기 쉽습니다.** 재작업 경로는 `writeTempJSON`을 거치지 않습니다.
2. **단계 D-1을 빠뜨리면 두 번째 저장부터 조용히 망가집니다.** 첫 저장은 정상이라 눈치채기 어렵습니다.
3. **`ValidateInfographic`에 관련 성구를 넣지 마십시오.** 0개가 정상이며, 검증 실패는 md를
   0바이트로 만듭니다.
4. **`qt := doc.QTSectionDoc`의 맵 공유**(B-1 주석 참조). 얕은 복사로 순서 의존을 없애십시오.
5. **md 수동 편집은 Step2 저장 시 사라집니다.** 사용자가 선택한 동작입니다. 저장 버튼 안내문에
   한 줄 넣을지는 단계 F에서 판단하십시오.
6. 저장소 전체가 CRLF입니다. **`gofmt -w`를 일괄 실행하지 마십시오.** 새로 만든 LF 파일만 포맷합니다.

## 완료 조건

- 장년 QT에서 Step1 저장 → `sermon_summary.md` 끝에 `## 관련 성구`가 한 줄로 붙는다
- 관련 성구가 없는 설교는 **섹션 없이** 기도로 끝난다
- Step2에서 관련 성구를 고치고 저장 → md에 반영된다
- **저장을 두 번 해도** 반영된다
- 재작업 → md가 관련 성구까지 복원된다
- 비장년은 md가 생기지 않는다 (종전과 동일)
- `temp.json`의 `version`은 여전히 `"1.0"`
