## 0. 먼저 — 지금 `var/temp`에서 확인된 것

검토에 앞서 실제 산출물을 재 봤습니다. **어제 바꾼 경로가 아직 한 번도 타지지 않았습니다.**

`var/temp/temp.json` (10-01 21:49):

```
metadata.infographic 의 키 : apply, core, extra, follow, guide, prayer   ← 6개
```

**LLM이 아직 옛 6필드를 내고 있습니다.** 그래서 `sermon_summary.md`의 길잡이·적용·기도는
QT 섹션이 아니라 **저장된 infographic에서 폴백으로** 렌더되었습니다. 근거는 내용 자체입니다.

| | `sermon_summary.md` | `temp.json`의 QT 섹션 |
|---|---|---|
| 길잡이 | **106자 / 2문장** | **302자 / 6문장** |
| 기도 | **80자 / 2문장** | **127자 / 3문장** |
| 적용 | "…시작한다 / …바꾼다" (**평서형**) | "…생각해봅시다 / …살펴봅시다" (**QT 형식**) |

즉 **N1("길잡이·기도가 QT 본문과 글자 그대로 같다")은 실제로는 확인되지 않았습니다.**
N2(제목 변경)는 렌더러가 하는 일이라 정상으로 보인 것이 맞습니다.

> **왜 6필드가 왔는가** — 프롬프트는 앱이 만들어 주지만, 실행은 사람이 복사해 붙여넣습니다.
> LLM 대화창에 **이전 프롬프트가 남아 있었거나**, 별도로 관리하시는 인포그래픽 프롬프트
> 문서(`doc/260928_…v6.md` 등)를 쓰셨을 가능성이 큽니다.

### 이것이 항목 1에 주는 의미

**길이 문제는 아직 본격적으로 드러나지도 않았습니다.** 폴백이 사라지고 QT 섹션에서 오기
시작하면 길잡이는 **106자 → 302자(약 3배)**, 기도는 **80자 → 127자**가 됩니다.

지금 "글자 수를 조절해야 했다"고 느끼신 것이 106자 기준이었다면, 새 경로에서는 **훨씬 심해집니다.**
항목 1을 먼저 처리하는 것이 맞습니다.

## 1. 항목 ① — 길잡이·기도 길이

### 1-1. 현재 규칙

[prompt_qt_json.go:478,492](../service/prompt_qt_json.go#L478) (장년):

```
Summary: 5-6 sentences, reverent and thoughtful
Prayer:  5-6 sentences including repentance, gratitude, petition
         Structure: 경배 → 회개 → 감사 → 간구
```

실측은 summary 302자(6문장), prayer 127자(3문장)였습니다. **summary가 특히 깁니다.**

### 1-2. 핵심 긴장 — 같은 텍스트가 두 매체를 섬깁니다

어제 결정으로 QT summary/prayer는 **주보와 인포그래픽 양쪽**에 쓰입니다.

```
sections[summary] ─┬─→ temp.html · PDF · PNG · DOCX · PPTX · extended.html   (주보)
                   └─→ sermon_summary.md 의 "말씀의 길잡이"                   (인포그래픽)
```

**QT 규칙을 줄이면 주보도 함께 짧아집니다.** 어제 검토 4-1에서 "설교요약문이 길어진다"를
대가로 적었는데, 그 대가가 이제 반대 방향의 요구로 돌아온 것입니다.

### 1-3. 선택지

| 안 | 방법 | 주보 | md | Step2 편집 반영 | LLM 필드 |
|---|---|---|---|---|---|
| **A. QT를 줄인다** | 장년 Summary/Prayer 규칙을 3~4문장으로 | **짧아짐** | 짧아짐 | 유지 ✓ | 3개 유지 |
| **B. 다시 분리** | infographic에 짧은 guide/prayer를 되살림 | 그대로 | 짧음 | **잃음** ✗ | 5개로 증가 |
| **C. 렌더에서 자름** | md에서 앞 N문장만 | 그대로 | 짧음 | 유지 | 3개 유지 |

**C는 권하지 않습니다.** 문장을 기계적으로 자르면 기도의 "아멘"이 날아가고, 경배→회개→감사→간구
구조가 중간에서 끊깁니다. 요약은 자르기가 아닙니다.

**B는 어제 얻은 것을 되돌립니다.** Step2에서 기도를 고쳐도 md가 안 바뀌던 문제가 되살아납니다.

→ **A를 권합니다.** 다만 **주보가 함께 짧아지는 것을 받아들이실 수 있는지**가 전제입니다.
   이건 제가 판단할 수 없습니다(결정 3-1).

### 1-4. "5줄 미만"을 프롬프트에 어떻게 적을 것인가

**줄 수는 프롬프트로 지시할 수 없습니다.** 마크다운에서 한 문단은 한 줄이고, 화면에 몇 줄로
보일지는 인포그래픽 도구의 폭이 정합니다. LLM이 셀 수 있는 것은 **문장 수와 글자 수**뿐입니다.

A4 기준 5줄 ≈ **한글 150~200자** ≈ **3~4문장**으로 환산했습니다.

```
Summary: 3-4 sentences, about 150-180 Korean characters
Prayer:  3-4 sentences, about 120-150 Korean characters
         Structure: 경배 → 회개 → 감사 → 간구 (compress, do not drop)
```

> **문장 수와 글자 수를 함께 적습니다.** 문장 수만 적으면 모델이 한 문장을 길게 늘여
> 결과가 그대로입니다. 글자 수만 적으면 문장이 토막 납니다.

**기도는 구조를 반드시 함께 유지시켜야 합니다.** 지금 규칙은 4단계(경배·회개·감사·간구)인데,
문장 수만 줄이면 모델이 단계를 **버립니다**. "압축하되 빼지 말 것"을 명시해야 합니다.

### 1-5. 비장년은 건드리지 않습니다

md는 **장년 전용**입니다([qtstep1_service.go:177](../service/qtstep1_service.go#L177)).
young_adult(4-5문장) · teen(3-4) · child(2-3)은 인포그래픽과 무관하므로 그대로 둡니다.

## 2. 항목 ② — 찬송가가 입력값을 무시한다

### 2-1. 사실 확인 — 로직이 "없어진" 것이 맞습니다

[a8c85a5 (2026-08-02) 프롬프트 전면 개편](../service/prompt_qt_json.go) 이전에는 프롬프트 앞머리에
**입력값을 그대로 나열하는 블록**이 있었습니다.

```
[Metadata]
Title={{title}}
Bible Passage={{bible_text}}
Hymn={{hymn}}          ← 이 줄이 사라졌습니다
Preacher={{preacher}}
...
```

개편하면서 이 블록은 **METADATA FIDELITY**로 대체되었는데, 그 보호 목록에 **hymn이 빠졌습니다**
([:159](../service/prompt_qt_json.go#L159)).

```
series / preacher / church_name / sermon_date / source_url / month_name / month_accent
                                                              ↑ hymn 없음
```

### 2-2. LLM이 지어내는 이유 — 네 가지가 겹쳐 있습니다

| # | 위치 | 문제 |
|---|---|---|
| 1 | [:197](../service/prompt_qt_json.go#L197) **JSON 스키마 템플릿** | `"hymn": "새찬송가 456장"` — **하드코딩된 예시**. series·bible_text·preacher 등은 모두 `{{...}}` 자리표시자인데 hymn만 구체적인 값이다. 모델은 템플릿을 베낀다 |
| 2 | [:159](../service/prompt_qt_json.go#L159) METADATA FIDELITY | hymn이 목록에 없다 → "지어내지 말 것" 보호를 못 받는다 |
| 3 | [:62](../service/prompt_qt_json.go#L62) 기본 프롬프트 | `Example: "새찬송가 324장"` — **또 다른 예시**. 입력을 복사하라는 말은 없다 |
| 4 | [:143](../service/prompt_qt_json.go#L143) 필드 규칙 | `Use {{hymn}} if provided; recommend 1 Korean hymn if empty` — 값이 치환되면 *"Use 새찬송가 324장 if provided; recommend 1 Korean hymn if empty"*가 되어 **두 지시가 한 줄에 공존**한다 |

**1번이 가장 유력합니다.** 모델에게 가장 강한 신호는 설명문이 아니라 **스키마 예시**이고,
거기 적힌 값이 456장입니다.

### 2-3. 코드에도 방어가 없습니다

시리즈·제목은 Step1 저장에서 **화면 입력을 doc에 확정**합니다
([qtstep1_service.go:99-110](../service/qtstep1_service.go#L99)). **찬송가는 하지 않습니다.**

그 결과 같은 저장에서 두 곳의 값이 **갈립니다**.

| 저장처 | 찬송가 |
|---|---|
| `history_master.hymn` | **화면 입력값** ([qtstep1_service.go:255](../service/qtstep1_service.go#L255)) |
| `temp.json`의 `metadata.hymn` | **LLM이 준 값** |

→ 작업내역 목록에 보이는 찬송과 실제 주보에 찍히는 찬송이 다를 수 있습니다.
   **9/5에 고친 시리즈 버그와 완전히 같은 모양입니다.**

> 확인법: 작업내역 목록의 찬송 값과 `var/temp/temp.json`의 `metadata.hymn`을 비교하면 즉시 보입니다.

### 2-4. 권장 — 프롬프트와 코드 양쪽

**프롬프트만 고치면 모델에 따라 또 샙니다.** 8/29 테스트에서 5개 모델 중 3개(유료 Claude 포함)가
메타정보를 날조했습니다. 코드로 막는 쪽이 확실합니다.

- **프롬프트** — 스키마 템플릿을 `"hymn": "{{hymn}}"`로, METADATA FIDELITY에 hymn을
  **조건부 항목**으로 추가, 예시 2곳 정리
- **코드** — Step1 저장에서 **화면 입력이 비어 있지 않으면** `doc.Metadata["hymn"]`에 확정

```go
// 찬송가는 조건부다. 입력이 있으면 사람 값이 이기고,
// 비어 있으면 LLM의 추천을 살린다.
if h := normalizeHymnText(req.Hymn); h != "" {
    doc.Metadata["hymn"] = h
}
```

**series·title과 다른 점은 "비어 있으면 LLM을 살린다"는 것뿐입니다.** 추천 기능은 그대로 둡니다.
