# 장년용 통합 프롬프트 (테스트용)

작성일: 2026-08-29
관련: [260829_S2QT_prompt_검토.md](260829_S2QT_prompt_검토.md)
목적: 통합안 채택 여부를 **실제 LLM 출력으로 판단**하기 위한 검증용 프롬프트

---

## 1. 이 문서의 위치

검토서의 통합안대로, `audience = "adult"`일 때 `BuildQTPromptJSON()`이 조립하게 될 프롬프트 전문입니다. 코드는 아직 손대지 않았으므로, 아래 프롬프트를 **수동으로 복사해 외부 LLM에 붙여 넣고** 결과를 보면 됩니다.

조립 구성은 다음과 같습니다. 3장의 코드 블록은 이 4개를 이미 합쳐 놓은 것입니다.

| 순서 | 블록 | 출처 | 상태 |
|---|---|---|---|
| 1 | 기본 프롬프트 | `var/conf/prompt_qt_json.md` (126행 전문) | 기존 |
| 2 | 장년 규칙 | `getAudiencePromptRules("adult")` ([prompt_qt_json.go:361-403](../service/prompt_qt_json.go#L361-L403)) | 기존 |
| 3 | JSON 출력 계약 | `defaultQTPromptJSONSchema` | 기존 + **infographic 추가** |
| 4 | **인포그래픽 계약** | 신규 | **신규** |
| 5 | 전사문 | `defaultQTPromptTranscript` | 기존 |

**신규는 4번 전체와 3번의 `infographic` 관련 부분뿐입니다.** 나머지는 현행과 동일하게 두어, 이번 테스트에서 달라지는 변수를 인포그래픽 추가 하나로 좁혔습니다.

> **참고 — 기존 코드의 불일치**
> 기본 프롬프트는 `var/conf/prompt_qt_json.md`(파일)와 `defaultQTPromptBase`(Go 상수) 두 곳에 있는데, **내용이 서로 다릅니다.** 파일에만 `[Input Metadata]`, `[Critical Content Scope]`, `[Output Rules]`, `[Content Processing Rules]`, `[Key Principles]` 5개 섹션이 있습니다.
> `loadQTPromptBaseTemplate()`이 파일을 우선 읽으므로 평소에는 파일 버전이 쓰이지만, 파일이 없는 배포 환경에서는 **5개 섹션이 빠진 약한 프롬프트로 조용히 동작합니다.** 이번 통합과는 무관한 기존 사안이나, 착수 시 함께 정리하는 편이 좋습니다.

## 2. 테스트 방법

### 2-1. 치환할 값

프롬프트 안의 `{{...}}`를 아래 값으로 바꿉니다. `var/temp/`에 남아 있는 실제 작업 데이터를 그대로 쓰면 편합니다.

| placeholder | 테스트 값 |
|---|---|
| `{{title}}` | `역경의 파도를 넘어 행복의 안식처로` |
| `{{bible_text}}` | `데살로니가후서 1:6~12` |
| `{{hymn}}` | `새찬송가 337장` |
| `{{preacher}}` | (비움) |
| `{{church_name}}` | `수원새빛교회` |
| `{{sermon_date}}` | `2026-07-26` |
| `{{source_url}}` | `https://www.youtube.com/watch?v=PmGeY1zLxXE` |
| `{{audience}}` | `adult` |
| `{{month_name}}` | `8월` |
| `{{month_accent}}` | `#C97A3D` |
| `{{raw_text}}` | **`var/temp/temp.txt` 전문**(약 24,000자)을 그대로 붙여 넣기 |

`{{month_name}}` / `{{month_accent}}`는 실행 시각 기준으로 코드가 자동 채우는 값입니다([prompt_qt_json.go:553-554](../service/prompt_qt_json.go#L553-L554)).

### 2-2. 절차

1. 3장 코드 블록 전체 복사
2. 위 표대로 치환 (`{{raw_text}}`는 맨 마지막에 붙임)
3. LLM에 1회 입력
4. 결과 JSON을 4장 체크리스트로 검증
5. `infographic` 객체를 5장 렌더 규칙에 따라 마크다운으로 옮겨, 6장 기대 산출물과 문체·분량 비교

### 2-3. 이 테스트로 확인할 것

검토서에서 "위험"으로 남겨 둔 항목들이 실제로 발생하는지 봅니다.

| # | 가설 | 확인 방법 |
|---|---|---|
| 1 | 한 번 호출로 QT 4섹션 + 인포그래픽 6필드가 모두 나온다 | 4장 체크리스트 A |
| 2 | **문체가 섞이지 않는다** — `apply`가 QT `reflection` 문체로 오염되지 않는다 | 4장 체크리스트 C (가장 중요) |
| 3 | 출력이 1.4~1.6배로 늘어도 잘림·누락이 없다 | 4장 체크리스트 A, JSON 유효성 |
| 4 | `follow`/`extra`/`core`가 `message`에서 복사되지 않고 독립적으로 작성된다 | 4장 체크리스트 D |
| 5 | 인포그래픽 블록에서 "설교"라는 단어가 나오지 않는다 | 4장 체크리스트 B |

2번이 실패하면 프롬프트 보강으로 해결 가능한지, 아니면 호출을 나눠야 하는지가 갈립니다. **통합안 채택의 핵심 판단 지점입니다.**

## 3. 통합 프롬프트 전문

아래 블록 전체를 복사해서 사용합니다.

```
[Role]
QT Writing Assistant (Korean Church)

[Task]
Convert ASR sermon transcript into structured QT (Quiet Time) JSON
content for church bulletin, meditation material, and blog publication.

[Important]
- This prompt works with any LLM (Claude, GPT-4o, Gemini, Mistral, etc.)
- Optimize output for accuracy, not model-specific features
- Ensure JSON validity for all parsers

[Language - CRITICAL for ALL LLMs]

Input Language: Korean (ASR transcript, may contain errors)
Output Language: NATURAL KOREAN ONLY (완벽한 자연스러운 한글)

MANDATORY OUTPUT RULES:
1. ✓ Every single value MUST be in Korean (완벽한 한글)
2. ✓ NO English words, phrases, or sentences anywhere
3. ✓ NO romanization (ㄱㄴㄷ only, not abc)
4. ✓ NO mixing languages in any field
5. ✓ If uncertain, generalize using simpler Korean (do NOT fall back to English)

SPECIFIC FIELD REQUIREMENTS:

metadata.title:
  Must start with "[QT] " + Korean title
  Example: "[QT] 주님의 사랑에 응답하는 삶"
  ❌ Wrong: "[QT] Love God's Word" or "[QT] God's Love (신의 사랑)"

sections[*].blocks[*].text (paragraph blocks):
  Natural Korean sentences with proper grammar
  Example: "여호사밧은 압도적인 적군을 앞두고도 자신을 바라보지 않았습니다."
  ❌ Wrong: "Jehoshaphat did not look at his abilities..."

sections[*].blocks[*].items (list items - reflection, etc):
  Format: "주어/목적어 + 동사 + 고 있는지 생각해봅시다/살펴봅시다/확인해봅시다"
  Example 1: "주님을 사랑하는 마음으로 고백하고 있는지 생각해봅시다."
  Example 2: "내 섬김이 의무가 아닌 진정한 사랑에서 비롯되는지 살펴봅시다."
  Example 3: "내 사랑이 주변 공동체를 세우고 강하게 하는지 확인해봅시다."
  ❌ Wrong: "Consider whether you confess your love for the Lord..."

metadata.hymn:
  Korean hymn name or standard Korean hymn format
  Example: "새찬송가 324장"
  Example: "주의 사랑을 담아"
  ❌ Wrong: "Hymn 456" or "Love Song (사랑의 노래)"

metadata.support_scriptures:
  Korean Bible verse references
  Example: ["마태복음 11:28", "요한복음 14:1"]
  ❌ Wrong: ["Matthew 11:28", "존11:1"]

metadata.support_scriptures_full[*].text:
  Complete Korean Bible verse text (from Korean Bible translation)
  Example: "수고하고 무거운 짐진 자들아 다 내게로 오라 내가 너희를 쉬게 하리라"
  ❌ Wrong: "Come to me, all you who are weary..."

CHINESE CHARACTERS:
✓ OK to use in Korean context: 기도(禱告), 회개(悔改), 영적(靈的), 적용(適用)
✗ NOT OK as shortcut: 心, 愛, 聖 (use Korean instead: 마음, 사랑, 거룩한)

TONE AND STYLE:
- Respectful, reverent, warm Korean
- Write like professional church bulletin or meditation material
- Natural Korean: use ~습니다, ~세요, ~해주세요 (polite endings)
- NOT formal/stiff Korean: avoid ~하라, ~할지어다
- NOT casual/slangy Korean: avoid 야, 근데, 뭐 등

WHAT TO DO IF UNSURE:
→ Use simpler, more common Korean words
→ Avoid complex theological jargon in English
→ Look for Korean equivalents
→ Do NOT fall back to English explanations

[Input Metadata]
Title: {{title}}
Bible Passage (scope): {{bible_text}}
Hymn: {{hymn}}
Preacher: {{preacher}}
Church: {{church_name}}
Sermon Date: {{sermon_date}}
Source URL: {{source_url}}
Target Audience: {{audience}}

[Critical Content Scope]
✓ Use ONLY {{bible_text}} as the QT foundation
✓ Extract meaning from context and repeated key messages
✓ Rewrite awkward sentences naturally
✓ Reflect repeated emphases

✗ Do NOT use verses outside {{bible_text}}
✗ Do NOT quote transcript literally
✗ Do NOT overstate uncertain details
✗ Do NOT create illustrative material not in transcript

[Output Rules]

1. JSON object only
2. No code blocks (remove backticks)
3. No HTML tags
4. No markdown formatting
5. Valid JSON syntax required
6. All text must be Korean (perfect grammar and spacing)

[Content Processing Rules]

- ASR errors: Fix through context. Example: "은혜"를 "은택"으로 잘못 들었다면, 문맥상 "은혜"가 맞는지 판단
- Uncertainty: When unsure about a detail, generalize instead of guessing. Example: "어떤 분이" instead of "김철수가"
- Main message: Clearly separate core truth from supporting examples
- Illustrations: Include only if directly supporting main message; otherwise summarize as one sentence
- Tone: Match audience (adult/young_adult/teen/child) in voice, word choice, and depth

[Key Principles]

- Clarity > Completeness. Missing perfect detail is better than incorrect content.
- Bible accuracy > Paraphrasing. Every verse reference must be within {{bible_text}}.
- Reader benefit > Structure. If 2 messages connect better than 3, use 2.
- Natural Korean > Literal translation. Write as a native would write.

[Audience: adult]

Target: Church members 40+, professionals, mature believers

Content Guidelines (KOREAN ONLY):

Title: MUST reuse the user-provided input title EXACTLY (제목은 입력값 그대로 사용)
- Set metadata.title to the input {{title}} verbatim — do NOT rewrite, shorten, rephrase, or "improve" it
- Preserve every word; only ensure it starts with "[QT] " (add the prefix if missing, otherwise change nothing)
- Create a new title ONLY when {{title}} is empty
- Format: "[QT] 제목"
- Example: "[QT] 주님의 사랑에 응답하는 삶"

Bible Passage: MUST reuse the user-provided input passage EXACTLY (본문성구는 입력값 그대로 사용)
- Set metadata.bible_text to the input {{bible_text}} verbatim — do NOT change the book, chapter, or verse range
- The QT foundation stays fixed to the originally entered passage

Summary: 5-6 sentences, reverent and thoughtful (모두 한글)
- Example: "여호사밧은 압도적인 적군을 앞두고도 자신을 바라보지 않았습니다."

Message: 3 points with 3-5 sentences each (완벽한 한글만)
- Each point connects to personal faith maturity
- Use theological depth appropriate to audience
- Examples: "삶의 경험에서 배우는 신앙", "리더십의 책임감", "가족 속의 신앙"

Reflection: 3 items for personal examination (한글 포맷 필수)
- Format: "주어/목적어 + 동사 + 고 있는지 생각해봅시다/살펴봅시다/확인해봅시다"
- Example 1: "주님을 사랑하는 마음으로 진정하게 고백하고 있는지 생각해봅시다."
- Example 2: "내 섬김이 의무가 아닌 진정한 사랑에서 비롯되는지 살펴봅시다."
- Example 3: "내 사랑이 주변 공동체를 세우고 강하게 하는지 확인해봅시다."

Prayer: 5-6 sentences including repentance, gratitude, petition (한글만)
- Tone: Serious, humble, warm
- Structure: 경배 → 회개 → 감사 → 간구
- Example: "주님, 나의 생각을 말씀으로 지켜주세요..."

Style: Warm, reverent, profound; avoid casual or trendy language
- Use: ~습니다, ~세요, ~해주세요 (polite Korean)
- Avoid: ~하라, ~할지어다 (formal old Korean)
- Avoid: 야, 근데, 뭐 (casual Korean)

⚠️ CRITICAL: No English words anywhere. If output contains English, regenerate in KOREAN ONLY.

[JSON Output Contract]

MANDATORY:
- Exactly one JSON object (no array, no multiple objects)
- No code blocks: JSON starts with { and ends with }
- UTF-8 encoded Korean text ONLY

STRUCTURE:
1. sections: exactly 4 sections in this exact order:
   a. "summary" (말씀의 길잡이)
   b. "message" (오늘의 메시지)
   c. "reflection" (깊은 묵상과 적용)
   d. "prayer" (오늘의 기도)

2. message.blocks: exactly 6 blocks (3 pairs of title + paragraph)
   [message_title, paragraph, message_title, paragraph, message_title, paragraph]

3. reflection.blocks: exactly 1 block with type "list" and 3 items

4. prayer.blocks: exactly 1 block with type "paragraph"

5. infographic: one object at the TOP LEVEL (sections 배열 안이 아니다).
   반드시 JSON의 가장 마지막에 배치한다. 상세 규칙은 [Infographic Contract] 참조.

METADATA RULES:
- title: Must start with "[QT] " + Korean title
- bible_text: Must exactly equal input {{bible_text}}
- bible_passage_text: Complete passage with ALL verses
  Format: "1절 [verse text]\n2절 [verse text]"
- hymn: Use {{hymn}} if provided; recommend 1 Korean hymn if empty; use "-" if unsure
- support_scriptures: Array of 0-3 Korean Bible references (strings), excluding {{bible_text}}
- support_scriptures_full: MUST be array of objects [{reference, text}]
  matching support_scriptures order

[Infographic Contract]

sections[] 와 별개로, 최상위에 "infographic" 객체를 하나 추가한다.
같은 전사문에서 뽑되, 아래 규칙은 QT 본문 규칙과 독립적으로 적용한다.
QT 본문에 쓴 문장을 그대로 복사하지 않는다. 분량과 문체가 다르기 때문이다.

■ 용어 고정
말씀의 길잡이 / 말씀을 따라 / 더하는 말씀 / 말씀의 핵심 / 오늘의 적용 / 오늘의 기도

■ 금지어 (이 객체 안에서만 적용. QT 본문에는 해당 없음)
"설교", "설교 흐름", "설교 예화" 를 쓰지 않는다. "말씀" 중심으로 표현한다.

■ 종결어미 (중요)
경어체(~합니다) : guide, prayer
평서체(~한다)   : follow, extra, core, apply
두 무리를 섞지 않는다.

■ 필드별 규칙

guide  (말씀의 길잡이)
  - 본문의 배경과 상황을 2~3문장으로 정리하고, 왜 이 말씀이 필요한지 설명한다.
  - 경어체(~합니다).
  - QT summary는 5~6문장이지만, 여기서는 반드시 2~3문장으로 줄여 다시 쓴다.
  - ✓ "우리는 예수님과 동행하며 살아갈수록 자신의 연약함을 더욱 절감합니다."

follow (말씀을 따라)  — 배열, 3~5개
  - 말씀의 흐름과 요점을 순서대로 정리한다. 각 항목은 완결된 한 문장.
  - 평서체(~한다).
  - ❌ "생각은 말씀으로 지키기"                    (명사구. message_title 형식이다)
  - ✓ "성령께서 우리의 연약함을 도우시며, 말할 수 없는 탄식으로 친히 간구하신다."

extra  (더하는 말씀)  — 배열, 0~3개 문단
  - 전사문에 실제로 등장한 예화만 정리한다. 없으면 빈 배열 [].
  - 예화가 본문 메시지를 어떻게 뒷받침하는지 함께 서술한다.
  - 말한 사람 본인의 이야기는 제3자 시점으로 바꾼다.
  - 평서체(~한다).
  - ❌ "제가 다리를 다쳤을 때 기도할 수 없었습니다."
  - ✓ "한 목회자는 골절 수술로 기도할 수 없던 때에 성령의 탄식을 경험했다."

core   (말씀의 핵심)  — 문자열, 한 문장
  - 명제형으로 단정한다. 평서체(~한다).
  - ✓ "하나님의 평강은 두려움 가운데서도 우리를 붙드신다."

apply  (오늘의 적용)  — 배열, 2~3개
  - 구체적이고 실천 가능한 행동으로 쓴다. 평서체(~한다).
  - ❌ "주님께 맡기고 있는지 생각해봅시다."          (QT reflection 형식이다)
  - ✓ "기도할 바를 모를 때 완벽한 문장을 만들지 말고 주의 이름을 부른다."

prayer (오늘의 기도)  — 문자열, 2~3문장
  - 말씀을 붙들고 실천하기를 다짐하는 기도문. 경어체(~합니다).
  - QT prayer는 5~6문장이지만, 여기서는 반드시 2~3문장으로 줄여 다시 쓴다.

■ 제목과 성경본문은 infographic 객체에 넣지 않는다.
  metadata.title 과 metadata.bible_text 를 재사용하므로 중복 작성하지 않는다.
```

## 5. infographic 객체 → 마크다운 렌더 규칙

받은 JSON을 눈으로 비교하기 위한 변환 규칙입니다. 구현 시 `InfographicService`가 이대로 렌더합니다.

| 마크다운 | 출처 | 형식 |
|---|---|---|
| `# {제목}` | `metadata.title`에서 `[QT] ` 제거 | H1 |
| `## 성경본문` + 본문 | `metadata.bible_text` | 참조만 (전문 아님) |
| `## 말씀의 길잡이` | `infographic.guide` | 문단 |
| `## 말씀을 따라` | `infographic.follow[]` | `- ` 목록 |
| `## 더하는 말씀` | `infographic.extra[]` | 문단, 항목 사이 빈 줄 |
| `## 말씀의 핵심` | `infographic.core` | 문단 |
| `## 오늘의 적용` | `infographic.apply[]` | `- ` 목록 |
| `## 오늘의 기도` | `infographic.prayer` | 문단 |

`extra`와 `prayer`처럼 여러 문장이 이어지는 문단은, 기대 산출물 샘플처럼 **줄 끝 공백 2칸**으로 줄바꿈을 유지합니다.

## 6. 기대 산출물 (비교 기준)

작업지시서에 첨부된 샘플입니다. 5장 규칙으로 렌더한 결과가 이 문서와 **같은 결의 문체·분량**이면 통과입니다. 본문이 다르므로 내용이 아니라 형태를 봅니다.

```markdown
# 내가 무너져도 성령은 일하신다

## 성경본문
로마서 8:26-28

## 말씀의 길잡이
우리는 예수님과 동행하며 살아갈수록 자신의 연약함을 더욱 절감합니다.
문제와 시험이 밀려올 때 어떻게 기도해야 할지조차 모르는 현실 속에서, 성령께서 우리 안에 오셔서 도우신다는 사실이 얼마나 놀라운 소식인지를 이 말씀은 선명히 보여 줍니다.
연약함 가운데서도 성령의 도우심을 붙잡을 때 삶의 여러 어려움을 이겨 나갈 수 있습니다.

## 말씀을 따라
- 성령께서 우리의 연약함을 도우시며, 우리가 마땅히 기도할 바를 알지 못할 때 말할 수 없는 탄식으로 우리를 위하여 친히 간구하신다.
- 성령께서 우리 안에 계시기 때문에 우리의 마음을 다 아시며, 하나님의 뜻대로 성도들을 위하여 간구하신다.
- 하나님을 사랑하는 자, 곧 그분의 뜻대로 부르심을 입은 자들에게는 모든 것이 합력하여 선을 이루게 하신다.
- 성령의 이 사역은 특별한 은사 체험 때만 아니라 평범한 일상 속에서도 계속 이루어진다.
- 우리는 그저 성령을 따라가며 "주님, 어떻게 할까요?" 하며 순종하면 된다.

## 더하는 말씀
한 목회자는 오른쪽 대퇴부 골절 수술 때와 교회에서 거짓 소문이 퍼져 낙심하고 분노하던 때, 성령께서 말할 수 없는 탄식으로 기도하시는 것을 경험했다.
"나는 죽었습니다"라는 고백이 터져 나오며 모든 분노와 좌절이 사라지고, 주님의 애통하는 마음을 알게 되었다.

또 한 선교사가 아이들과 함께 있는 장면에서는, 아이들이 그저 이름만 불러도 그들의 필요를 다 아는 모습이 그려졌다.
이는 우리가 기도가 잘 되지 않을 때 그저 주의 이름을 부르는 것만으로도 성령께서 우리의 속사정을 다 아시고 하나님께 아뢰신다는 사실을 뒷받침한다.

## 말씀의 핵심
내가 무너지고 연약해도 성령께서 나를 위해 기도하시고 내 마음을 아시며 모든 것을 합력하여 선을 이루신다.

## 오늘의 적용
- 문제가 닥쳐 기도할 바를 모를 때, 완벽한 문장을 만들지 말고 주의 이름을 부르며 성령의 탄식에 나를 맡긴다.
- "나는 하나님을 사랑하는가?"라는 한 가지에만 집중하고, 기도한 뒤 일어나는 모든 일을 "이것도 합력하여 선을 이루시는 과정"으로 믿기로 한다.
- 일상 속에서 "주님, 이 상황에서 어떻게 할까요?"라고 물으며 성령을 따라 한 걸음씩 순종한다.

## 오늘의 기도
아버지 하나님, 연약한 우리를 도우시려고 성령을 보내 주신 은혜에 감사드립니다.
내가 무너져도 성령께서 말할 수 없는 탄식으로 기도하시고 내 마음을 다 아시며 모든 것을 합력하여 선을 이루심을 믿습니다.
오늘도 성령을 따라가며 순종하게 하옵소서.
예수님의 이름으로 기도합니다.
```

### 이 샘플에서 도출한 규칙

프롬프트의 종결어미 규칙은 이 샘플을 실제로 분석해 뽑은 것입니다.

| 섹션 | 샘플 종결 | 분류 |
|---|---|---|
| 말씀의 길잡이 | `절감합니다`, `보여 줍니다`, `있습니다` | 경어체 |
| 말씀을 따라 | `간구하신다`, `이루어진다`, `되다` | 평서체 |
| 더하는 말씀 | `경험했다`, `그려졌다`, `뒷받침한다` | 평서체 |
| 말씀의 핵심 | `이루신다` | 평서체 |
| 오늘의 적용 | `맡긴다`, `믿기로 한다`, `순종한다` | 평서체 |
| 오늘의 기도 | `감사드립니다`, `믿습니다`, `기도합니다` | 경어체 |

QT 본문은 전부 경어체이므로, 규칙을 명시하지 않으면 LLM이 인포그래픽도 경어체로 통일해 버릴 가능성이 높습니다. 프롬프트에서 이 대비를 굵게 다룬 이유입니다.

| `prayer` | 경어체 | 기도**합니다** | 기도**합니다** | **하옵소서** | **해주세요** | 믿**습니다** |

| `apply` | 평서체 | 구한**다** 외 2 | 묻는**다** 외 1 | 나아간**다** 외 2 | 구한**다** 외 2 | 바라본**다** 외 2 |

**역방향 오염도 없습니다.** QT `reflection`의 점검형 어미가 5개 모델 × 3항목 = **15/15 그대로 유지**되었습니다. 인포그래픽 규칙이 QT 쪽으로 번지지 않았습니다.

무료·유료를 가리지 않고 5종 전부 동일하게 나왔으므로, **6장에서 도출한 종결어미 규칙은 확실히 작동합니다.** 이 항목은 더 검증할 필요가 없다고 봅니다.

주목할 점은 **QT 본문의 분량 규칙(summary 5~6문장)은 Claude가 어겼는데, 인포그래픽의 분량 규칙(guide 2~3문장)은 5종 모두 지켰다**는 것입니다. 신규 작성한 `[Infographic Contract]`가 기존 장년 규칙보다 오히려 준수율이 높습니다.

### 8-4. D. 독립성 — Copilot(무료) 단독 실패, 유료 2종은 통과

각 인포그래픽 문장이 QT 섹션과 겹치는 **최장 공통 문자열** 길이입니다.

| 비교 | Grok | Gemini | Copilot | ChatGPT | Claude |
|---|---|---|---|---|---|
| `guide` ↔ `summary` | 29 | 17 | 11 | 0 | 18 |
| `prayer` ↔ QT `prayer` | 20 | 18 | 0 | 33 | 10 |
| `follow[*]` ↔ `message` | 15, 16, 0, 10, 11 | 0, 12, 0, 0 | **21, 25, 15, 22** | 10, 0, 10, 16, 0 | **0, 0, 0, 0** |
| `core` ↔ `message` | 0 | 16 | 12 | 15 | 0 |

Copilot은 `message` 문단을 **어미만 바꿔** `follow`로 옮겼습니다.

```
message : "두려움은 현실을 왜곡시키고 미래를 불안하게 만듭니다."
follow  : "두려움은 현실을 왜곡시키고 미래를 불안하게 만든다."
```

4개 항목 중 4개가 모두 이 패턴이라 우연이 아닙니다.

**유료 2종은 이 패턴이 전혀 없습니다.** 특히 Claude는 `follow` 4항목 모두 QT `message`와 **공통 문자열 0자** — 완전히 독립적으로 작성했습니다. ChatGPT도 최대 16자에 그칩니다.

> **판정 정정** — 앞선 무료 3종 테스트에서는 이 실패가 "프롬프트 결함인지 모델 한계인지" 보류 상태였습니다. 유료 2종이 통과함으로써 **Copilot의 무료 모델 지시 준수 한계**로 결론 났습니다. 프롬프트 수정은 **필수가 아닙니다.**
>
> 다만 무료 등급으로 운영한다면 여전히 발생하므로, ❌ 예시 한 줄 추가는 **저비용 보험**으로 남겨 둘 만합니다.

Grok의 `guide`↔`summary` 29자와 ChatGPT의 `prayer` 33자는 **위반이 아닙니다.** 도입부·상용구를 재사용했지만 분량 압축(5~6문장 → 2~3문장)은 규칙대로 이루어졌습니다.

### 8-6. 통합과 무관한 품질 문제

인포그래픽 **바깥**(QT 본문·메타데이터)에서 나온 문제들입니다. 통합 때문에 생긴 것이 아니라 모델 자체의 품질 차이이므로, 통합안 판단과 분리해 기록합니다.

| 모델 | 등급 | 문제 | 심각도 |
|---|---|---|---|
| Gemini | 무료 | `bible_passage_text` 2절에 영어 `captures` 삽입 + "여고생들"(원문: "젊거나 늙은 여인들") — **성경 본문 왜곡** | 높음 |
| Copilot | 무료 | `preacher: "홍길동 목사"`, `source_url: "https://example.com/sermon"` — **날조** | 높음 |

| **Claude** | **유료** | `preacher: "김신일 목사"`, `church_name: "하늘가족교회"`, `sermon_date: "2023-05-14"`, `source_url: "https://youtu.be/example"` — **날조** | 높음 |

#### 등급이 해결해 주지 않습니다

**유료 Claude가 무료 Copilot과 똑같이 메타데이터를 날조했습니다.** 5종 중 날조 3종(Gemini·Copilot·Claude), 중립 처리 2종(Grok·ChatGPT)으로, 등급과 상관관계가 없습니다.

원인은 명확합니다. 현행 프롬프트에는 `hymn`에만 처리 규칙이 있고(`{{hymn}}` 없으면 추천, 모르면 `"-"`), **`preacher` / `church_name` / `sermon_date` / `source_url` / `month_*`에는 아무 규칙이 없습니다.** 규칙이 없으니 모델이 알아서 채웁니다.

날조가 실제 피해로 이어지는 경로도 확인했습니다. `buildStep2Payload()`는 기본정보가 비어 있으면 **temp.json에서 읽은 값을 그대로 채택**합니다.

[frontend/src/components/qt/bindQTStep2.js:151-154](../frontend/src/components/qt/bindQTStep2.js#L151-L154)
```js
preacher:   (basicInfo.preacher   || loadedMeta.preacher   || '').trim(),
churchName: (basicInfo.churchName || loadedMeta.churchName || '').trim(),
```

사용자가 기본정보에 설교자·교회명을 입력하지 않았다면, **LLM이 지어낸 "김신일 목사" / "하늘가족교회"가 최종 산출물(PDF·PNG·blog)에 그대로 실립니다.** 교회 주보로 나가는 문서라 그냥 넘길 수 없는 문제입니다.

**보강 규칙 (권장)**

```
[Metadata Fidelity]
preacher / church_name / sermon_date / source_url / month_name / month_accent
- 입력으로 주어진 값을 그대로 복사한다.
- 입력이 비어 있으면 빈 문자열 "" 을 유지한다.
- 어떤 경우에도 추측하거나 지어내지 않는다.
- month_accent 는 "#RRGGBB" 형식의 색상 코드다. 다른 형태의 값을 넣지 않는다.
```

통합과 별개 항목이지만, 같은 프롬프트 파일을 손대는 김에 함께 처리하기를 권합니다.
