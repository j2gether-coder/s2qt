## 1. 착수 전 정정 및 신규 발견

### 1-1. 정정 — 프롬프트 스키마 블록은 Go 상수에만 있다

8/29 검토는 "프롬프트 원문이 Go 상수와 `var/conf/*.md` 두 곳에 중복 존재하므로 양쪽을 함께 갱신해야 한다"고 했으나, **부분적으로만 맞습니다.**

`loadQTPromptBaseTemplate()`([prompt_qt_json.go:268-290](../service/prompt_qt_json.go#L268-L290))이 파일로 덮어쓰는 것은 **`defaultQTPromptBase` 블록 하나뿐**입니다. `BuildQTPromptJSON()`은 나머지를 Go 상수에서 직접 가져옵니다.

[prompt_qt_json.go:529-540](../service/prompt_qt_json.go#L529-L540)
```go
basePrompt     := loadQTPromptBaseTemplate()          // ← var/conf/prompt_qt_json.md 로 덮어쓰기 가능
audienceRules  := getAudiencePromptRules(meta.Audience)  // ← Go 상수 전용
schemaPrompt   := defaultQTPromptJSONSchema              // ← Go 상수 전용 (version·스키마가 여기 있음)
transcriptPrompt := defaultQTPromptTranscript            // ← Go 상수 전용
```

**인포그래픽 블록과 `version` 값은 전부 `defaultQTPromptJSONSchema` 영역에 들어가므로, `var/conf/prompt_qt_json.md`는 손대지 않아도 됩니다.** 이중 관리 부담이 없어져 작업 1이 예상보다 단순합니다.

### 1-2. 정정 — `createDefaultOutput()`에는 인포그래픽 키가 없다

[appState.js:66-74](../frontend/src/state/appState.js#L66-L74)에는 `htmlFile` / `pdfFile` / `docxFile` / `pptxFile` / `pngFile`만 있습니다. `blogFile`·`infographicFile`은 [bindQTStep3.js:145-146](../frontend/src/components/qt/bindQTStep3.js#L145-L146)에서 동적으로 추가되고 있습니다. **제거 대상은 `bindQTStep3.js` 한 줄뿐입니다.**

### 1-3. DB 스키마는 변경하지 않는다 (2026-08-31 확정)

**Step1 원본은 기존 `history_qt_json` 테이블에 그대로 저장합니다.** 초안에서 권했던 별도 테이블 `history_llm_json` 신설은 **철회되었습니다.**

분리를 제안한 근거는 ① 두 포맷의 동시 혼재 ② 구분 컬럼 추가 불가(`ALTER` 경로 없음) 두 가지였는데, **둘 다 "Step2도 DB에 쓴다"는 전제에서 나온 것**입니다. 결정 2로 Step2가 DB를 쓰지 않게 되면서 두 포맷은 동시에 공존하지 않고 **시간순으로 갈립니다.**

- 옛 이력 = 전부 평면 / 신규 이력 = 전부 원본
- `SaveHistory()`가 master와 json을 함께 INSERT하고 `UpsertHistoryQTJSON()`은 호출되지 않으므로 **master 1건당 json 행은 정확히 1개**
- 연령대는 **왼편 네비게이션 메뉴에서 정해져** `audience` 컬럼에 그대로 들어가므로 컬럼 추가가 필요한 지점이 없음

남는 일은 "뽑은 1행이 어느 포맷인지" 가리는 것뿐이며, 이는 단계 E에서 3줄로 처리합니다.

### 1-4. 단일 테이블이라 발생하지 않는 문제 3건

분리를 택했다면 **전부 손봐야 했을** 지점입니다. 기록으로 남깁니다 — 앞으로 이 테이블 구조를 바꾸려 할 때 같은 함정을 다시 밟지 않기 위해서입니다.

## 3. 단계별 작업 지시

각 단계는 **끝난 시점에 빌드가 통과**하도록 구성했습니다. 단계 사이에 커밋하십시오.

### 단계 A — 통합 프롬프트 (0.75일)

**목표**: adult 실행에서만 인포그래픽을 요구하는 프롬프트를 만든다. 다른 연령대의 출력은 **한 글자도 바뀌지 않아야 한다.**

- **A-1** `defaultQTPromptInfographic` 상수 신설. 내용은 [검토 문서 8장 초안](260829_S2QT_prompt_검토.md)과 [보강안](260829_S2QT_장년용_공통_통합프롬프트_보강안.md)의 `[INFOGRAPHIC CONTRACT]` 기준. **첫 줄에 version 오버라이드를 명시**한다.
  ```
  [Infographic Output Contract — adult only]

  이 블록이 있는 실행에서는 "version" 값을 "1.0"이 아니라 "1.1"로 출력한다.
  sections[] 와 별개로 최상위에 "infographic" 객체를 추가하며, 이를 JSON의 마지막 필드로 둔다.
  ```
- **A-2** `BuildQTPromptJSON()`([prompt_qt_json.go:526](../service/prompt_qt_json.go#L526))에 분기 추가.
  ```go
  parts := []string{basePrompt, audienceRules, schemaPrompt}
  if strings.TrimSpace(meta.Audience) == "adult" {
      parts = append(parts, strings.TrimSpace(defaultQTPromptInfographic))
  }
  parts = append(parts, transcriptPrompt)
  prompt := strings.Join(parts, "\n\n")
  ```
- **A-3** `defaultQTPromptJSONSchema`에 **METADATA FIDELITY 규칙 보강**. 8/29 실측에서 5개 모델 중 3개가 `preacher`·`church_name`·`sermon_date`·`source_url`을 날조했고(유료 Claude 포함), 현행 프롬프트에는 `hymn` 외 규칙이 없습니다. 보강안 `[METADATA FIDELITY — CRITICAL]` 블록을 이식합니다. **통합과 무관하나 교회 주보로 배포되는 문서이므로 이번에 함께 처리합니다.**

**완료 조건**: adult로 프롬프트를 뽑으면 인포그래픽 블록과 `1.1` 지시가 보이고, teen으로 뽑으면 **작업 전과 문자열이 완전히 동일**하다.

### 단계 B — 타입 및 렌더러 (0.75일)

**목표**: v1.1 JSON을 파싱해 infographic.md를 만드는 순수 함수를 완성한다. 아직 아무도 호출하지 않아도 된다.

- **B-1** `types.go`에 `InfographicData` 추가.
  ```go
  type InfographicData struct {
      Guide  string   `json:"guide"`
      Follow []string `json:"follow"`
      Extra  []string `json:"extra"`
      Core   string   `json:"core"`
      Apply  []string `json:"apply"`
      Prayer string   `json:"prayer"`
  }
  ```
- **B-2** `qtstep2_service.go`에 `QTLLMDoc` 추가. **임베딩을 쓰면 QT 부분 분리가 공짜로 됩니다** — `QTSectionDoc`에는 `Infographic` 필드가 없으므로 그대로 마샬하면 인포그래픽이 자동으로 빠집니다.
  ```go
  type QTLLMDoc struct {
      QTSectionDoc
      Infographic *InfographicData `json:"infographic,omitempty"`
  }
  ```
- **B-3** `ValidateInfographic(*InfographicData) []string` 신설 — 위반 사유 목록을 반환(빈 슬라이스면 통과). 검사 항목은 [검토 문서 8장 QUALITY CHECKS](260829_S2QT_prompt_검토.md)와 1:1 대응: `follow` 3~5개, `apply` 2~3개, `extra` 0~3개, `guide`/`core`/`prayer` 비어 있지 않음.
- **B-4** `InfographicService.BuildInfographicMD()`를 **렌더러로 교체**. 입력은 `(*InfographicData, title, bibleText)`, 출력은 md 문자열. 파일 쓰기는 호출부(단계 C)가 맡습니다. `loadTranscript()`·`loadMetadata()`·`infographicDoc`·`infographicMetadata`는 제거하고 `stripQTTitlePrefix()`는 남깁니다.
- **B-5** `prompt_infographic.go`의 `BuildInfographicPrompt()` 호출 지점을 끊습니다. 상수와 파일은 보존하되, 코드에서 참조하지 않습니다(확정 8). `AppConfig.PromptInfographicFile`은 남겨 두어도 무방합니다.

**출력 포맷 (엄수)** — 8/29 작업지시서 첨부 샘플 기준

```markdown
# {title}

## 성경본문
{bible_text}

## 말씀의 길잡이
{guide}

## 말씀을 따라
- {follow[0]}
- {follow[1]}

## 더하는 말씀
{extra[0]}

{extra[1]}

## 말씀의 핵심
{core}

## 오늘의 적용
- {apply[0]}
- {apply[1]}

## 오늘의 기도
{prayer}
```

- `title`은 `[QT] ` 접두어를 뗀 값(`stripQTTitlePrefix`)
- `follow`·`apply`는 `- ` 불릿, `extra`는 **문단**(빈 줄 구분)
- `extra`가 비면 `## 더하는 말씀` 섹션 **자체를 생략**

**완료 조건**: `go test ./service/` 통과. 샘플 JSON을 넣으면 위 포맷과 일치하는 md가 나온다.

### 단계 C — Step1 저장 재구성 (0.6일)

**목표**: 저장 경로를 하나로 모으고, 수동/API 두 진입점이 같은 함수를 타게 한다.

- **C-1** `service/qtstep1_service.go` 신설.
  ```go
  type QTStep1SaveRequest struct {
      Audience, Title, BibleText, Hymn,
      Preacher, ChurchName, SermonDate, SourceURL string
      JSONText string
  }

  type QTStep1SaveResult struct {
      TempJSONPath    string
      InfographicPath string   // 생성하지 않았으면 ""
      HistoryID       int64
      Warnings        []string // 화면에 노출하지 않고 로그에만 사용 (결정 5)
  }
  ```

  **저장 순서를 반드시 지킬 것** (함정 1 — 부분 저장 방지)
  ```
  1. 필수값 검증        : Audience / Title / BibleText 비었으면 즉시 에러
  2. JSON 정리·파싱     : CleanLLMJSONOutput → QTLLMDoc 언마샬 (실패 시 즉시 에러, 파일 안 건드림)
  3. temp.json 쓰기     : doc.QTSectionDoc 의 Version 을 "1.0" 으로 세팅 후 마샬
  4. infographic.md     : 항상 os.Truncate(path, 0) → 조건 충족 시에만 write
  5. DB 저장            : 원본 JSONText 를 그대로 보관
  ```

  **4번 생성 조건 (2중)** — 8/29안의 3중 게이트는 필요 없습니다.
  ```go
  if audience == "adult" && doc.Infographic != nil && len(ValidateInfographic(doc.Infographic)) == 0 {
      write()
  } else {
      LogWarn(...)   // 화면 표시 없음 (결정 5)
  }
  ```

## 5. 주의사항

1. **`frontend/src/wailsjs/` 직접 편집 금지.** `SaveManualLLMResult` 시그니처를 바꾸면 `wails dev` 또는 `wails build`로 바인딩을 재생성해야 프론트에서 새 인자를 넘길 수 있습니다.
2. **기존 DB를 백업하고 시작하십시오.** `var/db/s2qt.db`를 복사해 두면 S5(구버전 이력 재작업) 검증에 그대로 씁니다.
3. **비장년 회귀를 매 단계 확인하십시오.** 이번 변경의 이득은 전부 장년에 있고, 나머지 3개 연령대는 **출력이 1바이트도 달라지면 안 됩니다.**
4. **단계 C-3(API 경로)을 빠뜨리기 쉽습니다.** 수동 붙여넣기만 테스트하면 통과해 버립니다.
5. `os.Truncate`는 파일이 없으면 에러를 반환합니다. `os.IsNotExist(err)`는 무시하십시오.
6. 현재 작업 트리에 **미커밋 변경 10건**이 있습니다. 착수 전에 정리하면 이번 변경의 diff를 읽기 쉽습니다.
