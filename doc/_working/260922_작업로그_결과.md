## 단계 A — 렌더러

**`types.go`** — `SermonSummaryMeta` 신설. `InfographicData` 바로 아래에 두었습니다.

```go
type SermonSummaryMeta struct {
	Series            string   // 화면 입력. 비면 줄 자체를 생략
	Title             string   // 장년은 화면 입력, 비장년은 LLM 제목
	BibleText         string   // 화면 입력
	SupportScriptures []string // LLM 출력 → Step2에서 편집 가능. 0개가 정상
}
```

**`infographic_service.go`**

- `RenderInfographicMD(data *InfographicData, meta SermonSummaryMeta) string`
- 기도 섹션을 `"\n"` → `"\n\n"`로 바꾸고, 반환 직전 `TrimRight` + `"\n"` 하나로 정규화
- `writeInfographicInline()` 신설 — 기존 두 헬퍼와 같은 계약(비면 아무것도 쓰지 않음)
- `normalizeBibleRefSlice`를 **렌더러 안에서** 호출

마지막 항목이 지시서와 다릅니다. 호출부에서 정규화하도록 쓰여 있었는데, 그러면 **두 호출부가
각자 기억해야 합니다.** 한쪽이 빠뜨리면 md의 성구 표기만 다른 산출물과 어긋나는데, 이건 테스트가
아니라 눈으로만 잡히는 종류입니다. 렌더러 안에서 한 번 호출하면 구조적으로 불가능해집니다.

## 단계 B — Step1

`writeTempJSON`이 `metadata.infographic`을 싣습니다. **게이트 2개(장년 · 검증 통과)를 통과했을 때만** 넣습니다.

```go
qt.Metadata = copyMetadata(doc.Metadata)

if audience == AudienceAdult && len(ValidateInfographic(doc.Infographic)) == 0 {
	qt.Metadata["infographic"] = doc.Infographic
}
```

`copyMetadata()`는 지시서 함정 4에 대한 것입니다. `qt := doc.QTSectionDoc`는 얕은 복사라
**같은 맵을 가리킵니다.** 복사하지 않으면 `doc.Metadata`에도 키가 생기고, 그 doc이 그대로
작업내역 DB에 직렬화됩니다. 동작은 같지만 **`saveHistory`가 `writeTempJSON` 뒤에 실행된다는
순서 의존**이 생깁니다. 복사로 없앴습니다.

`writeSermonSummary`는 `doc.Metadata`에서 관련 성구를 꺼내 넘깁니다. 시리즈·제목·본문 성구는
종전대로 **화면 기본정보**에서 오고, 관련 성구만 화면 입력이 아니라 LLM 출력에서 옵니다.

## 단계 C — 재작업

**C-2가 지시서보다 중요했습니다.** `restoreQTSectionDoc()`에도 같은 주입을 넣었습니다.

```go
qt.Metadata = copyMetadata(doc.Metadata)
if qt.Audience == AudienceAdult && len(ValidateInfographic(doc.Infographic)) == 0 {
	qt.Metadata["infographic"] = doc.Infographic
}
```

여기서 `doc.Audience`가 아니라 **`qt.Audience`** 를 봅니다. 바로 위에서 빈 값을 인자
`audience`로 채운 뒤라, 이력 JSON에 audience가 비어 있어도 올바르게 판정됩니다.

`restoreInfographicFile()`의 폴백 로직은 구조를 유지한 채 대상만 구조체로 바꿨습니다.

## 단계 D — Step2 저장 시 md 재생성

- `preserveInternalBlogFields` → **`preserveInternalMetaFields`** 로 개명하고 `infographic` 추가.
  이름에 `blog`가 남아 있어 `extended.html` 개명과 어긋나 있었습니다.
- `Save()`가 temp.json을 **성공적으로 쓴 뒤** `rewriteSermonSummary(doc.Metadata)` 호출
- `getInfographicFromMap()` — 값이 `*InfographicData`(방금 넣음)일 수도 `map[string]any`(파일에서
  읽음)일 수도 있어 재마샬로 통일
- `copyMetadata()` / `getInfographicFromMap()`은 다른 맵 헬퍼들 옆(`qtstep2_service.go`)에 두었습니다

`rewriteSermonSummary`는 **실패해도 저장을 되돌리지 않습니다.** temp.json·temp.html은 이미
정상이고 md는 부수 산출물입니다. 로그만 남깁니다.

## 작업 중 판단한 것

### 1. 관련 성구 정규화를 렌더러 안으로 옮겼다

단계 A 참조. 지시서와 다른 유일한 설계 변경입니다.

### 2. `var/conf/prompt_infographic.md`는 손대지 않았다

지시서 단계 F를 확인해 보니 **`prompt_sermon_summary.md`라는 파일은 없었습니다**(검토서에서
이름을 잘못 적었습니다). 실제 파일은 `var/conf/prompt_infographic.md`이고,
[prompt_infographic.go:19-21](../../service/prompt_infographic.go#L19-L21)에 **"이 파일의 함수는
어디에서도 호출하지 않는다 / 작성 규칙 참고용으로만 남긴다"** 고 명시되어 있습니다.

그리고 이번 변경은 **LLM 계약을 바꾸지 않습니다.** `support_scriptures`는 이미 통합 프롬프트가
내놓는 필드이고, 우리가 그것을 렌더 단계에서 한 줄 더 쓰는 것뿐입니다. 프롬프트 문서를 고칠
이유가 없어 두었습니다.

### 3. Wails 재생성 불필요

공개 메서드 시그니처가 바뀌지 않았습니다. 프런트엔드 변경도 없습니다.

## 추가 조치 — `go test`가 `var/temp/`를 오염시키던 문제

앱 테스트 중 `var/temp/`에 **산출물에서 제외한 파일 4개**가 발견되었습니다.

```
temp.docx · temp.pptx · temp_office_docx.json · temp_office_pptx.json
```

### 원인 — Step2도 Step3도 아니었다

타임스탬프가 결정적이었습니다.

```
temp.docx · temp.pptx · temp_office_*.json   21:30:27   ← go test
temp.txt                                     21:53:43   ┐
temp.json · sermon_summary.md · temp.html    22:05:15   ├ 실제 앱 세션
temp.md / extended.html                      22:05:20 / :28  ┘
```

네 파일이 **같은 초에**, 앱 세션보다 23분 먼저 생겼습니다.

`MakeDOCXFromJSON` / `MakePPTXFromJSON`의 **유일한 호출자는 `word_test.go` / `ppt_test.go`** 이며,
프로덕션 코드에는 호출부가 없습니다. 두 테스트는 실제 `../var/temp/temp.json`을 읽고 같은 폴더에
산출물을 씁니다.

그리고 **Step3는 DOCX/PPTX를 만들지 않습니다.**
[qtstep3_service.go:129-141](../../service/qtstep3_service.go#L129-L141)이
`"DOCX 생성은 아직 연결되지 않았습니다."`를 반환합니다. 이번 Step2 변경이 쓰는 파일은
`sermon_summary.md` 하나뿐입니다.

### 조치

1. `word_test.go` / `ppt_test.go`를 **`S2QT_OFFICE_TEST=1`일 때만** 실행하도록 막았습니다.
   삭제하지 않은 이유는 DOCX/PPTX를 다시 연결할 때 쓸 스모크 테스트이기 때문입니다.
   `temp.json` 부재 시 `Fatal` → `Skip`으로 바꿨습니다(**깨끗한 체크아웃에서 실패하던 테스트**였습니다).
2. 남은 파일 4개를 삭제했습니다. 재실행 후 `var/temp/`의 타임스탬프가 **하나도 바뀌지 않음**을 확인했습니다.
3. [파일맵](../260922_S2QT_파일맵.md)을 정정했습니다 — DOCX/PPTX를 "Step3 산출물"로 적은 것이
   틀렸습니다. 미연결로 바로잡고 **지뢰 8번**(var/temp의 낯선 파일은 `go test`를 의심하고
   타임스탬프부터 볼 것)을 추가했습니다.

> 파일맵 §12에 "테스트가 실제 `var/temp/`를 건드린다"는 주의를 써 놓고, 정작 그 조건을 이미
> 어기고 있던 기존 테스트 두 개는 확인하지 않았습니다.
