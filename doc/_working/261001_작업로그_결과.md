## 단계 A — 프롬프트 5곳

`defaultQTPromptInfographic`에서 5곳을 고쳤습니다.

| 위치 | 변경 |
|---|---|
| 용어 고정 | `말씀을 따라 / 더하는 말씀 / 말씀의 핵심` 3개만 |
| 문체 | `guide, prayer` 줄 삭제 → `follow, extra, core : 평서형 단정` |
| 필드 규칙 | `guide` · `apply` · `prayer` 항목 삭제 (QT 참조 문구도 함께 사라짐) |
| 템플릿 | 3필드 |
| QUALITY CHECKS | 3필드 기준 + `✓ infographic 에 guide / apply / prayer 를 넣지 않았다` |

마지막 체크 항목은 지시서에 없던 것을 추가했습니다. **필드를 빼라는 지시는 "없음"을 적극적으로
확인해 주지 않습니다.** 모델이 습관적으로 6필드를 내는 것을 막는 쪽이 확실합니다.

"QT 본문과 독립적으로 다시 쓴다"([:298-306](../../service/prompt_qt_json.go#L298)) 규칙은
남은 3필드에 그대로 적용되므로 유지했습니다.

## 단계 B — 타입과 렌더러

**`InfographicData`는 줄이지 않았습니다.** 지시서대로 프롬프트에서만 빼고 구조체에는
`omitempty`로 남겼습니다. 주석에 "지우지 말 것"과 그 이유를 적었습니다.

`SermonSummaryQT` 신설. `SermonSummaryMeta`와 섞지 않았습니다 — 한쪽은 머리말·꼬리말,
다른 쪽은 본문입니다.

`RenderInfographicMD(data, qt, meta)` — 인자 셋의 출처가 각각 다릅니다(LLM 생성분 /
QT 재활용분 / 화면 기본정보). 주석에 표로 적어 두었습니다.

`ValidateInfographic`에서 guide/prayer/apply 검사를 제거하고 `infographicApplyMin/Max`
상수도 지웠습니다.

**`writeInfographicParagraph()` 신설** — 지시서에 함수 이름까지는 없었지만, 길잡이·기도가
비었을 때 제목만 남는 것을 막아야 했습니다(B-5). 기존 세 헬퍼와 같은 계약입니다.

## 단계 C — 조립과 호출부 3곳

`resolveSermonSummaryQT()` 한 곳에만 폴백을 두었습니다. 우선순위는 **저장된 값이 있으면 이긴다.**

호출부 3곳이 모두 같은 함수를 지나갑니다.

| 호출부 | 인자 |
|---|---|
| Step1 `writeSermonSummary` | `doc.Infographic, doc.Sections` |
| 재작업 `restoreInfographicFile` | `doc.Infographic, doc.Sections` |
| Step2 `rewriteSermonSummary` | `doc.Infographic(metadata에서), doc.Sections` |

**Step2가 `metadata` 대신 `doc` 전체를 받도록 바꿨습니다**(C-4). 이번 작업의 실질적 이득입니다.

### Load()의 중복 추출도 함께 정리했습니다

지시서가 "가능하면"이라고 한 부분입니다. `firstParagraphText` / `firstListItems`를 빼면서
`Load()`의 인라인 추출 3곳을 그 헬퍼로 바꿨습니다. 같은 패턴의 **세 번째 사본을 만들지 않았습니다.**

덤으로 동작이 하나 정확해졌습니다 — `Load()`는 `sec.Blocks[0].Text`를 **타입 확인 없이**
읽고 있었습니다. 새 헬퍼는 `type == "paragraph"`인 블록을 찾습니다.

## 작업 중 판단한 것

### 1. `var/conf/prompt_qt_json.md`는 고칠 것이 없었다

단계 E로 열어 보니 **infographic 언급이 한 건도 없습니다.** 인포그래픽 기능 도입 이전의
사본이며 코드도 읽지 않습니다. 지시서가 "여력이 되면"이라고 한 항목인데, 할 일 자체가 없었습니다.

### 2. gofmt 지적 3건은 제 변경과 무관하다

`types.go` · `infographic_service.go` · `qtstep2_service.go`가 지적되지만, 손대지 않은
`qtstep3_service.go` · `pdf_service.go` · `llm_service.go`도 똑같이 지적됩니다.
저장소 전역 CRLF 문제입니다. 신규 LF 파일만 확인했고 지적은 없었습니다.

**N4는 옛 이력이 있어야 확인됩니다.** 9월에 저장한 장년 이력을 재작업해 보십시오.

> **알려진 동작** — 옛 이력을 재작업한 뒤 Step2에서 길잡이·기도를 고쳐도 md에는 반영되지
> 않습니다. 저장된 값이 이기기 때문입니다(폴백 선택의 결과). 새 이력에서는 반영됩니다.
