## 추가 작업 — 화면 구성 수정 (2026-09-05, 앱 테스트 전)

사용자가 화면을 먼저 살펴보고 요청한 4건입니다.

### 1. 기본정보 입력란 순서 — 필수 항목을 상단으로

| 이전 | 변경 |
|---|---|
| 시리즈 / 제목* | **제목\* / 본문 성구\*** |
| 본문 성구* / 찬송 | **시리즈 / 찬송** |
| 설교자 / 교회명 | 설교자 / 교회명 |
| 설교일 | 설교일 |

시리즈를 제목 앞에 두었더니 **필수 항목 2개가 아래로 밀려나** 있었습니다. 필수를 첫 줄에 모았습니다.

### 2. 설교일 — 오늘 날짜 기본값 + 요일 표시

- `appState`의 `basicInfo.sermonDate` 기본값을 **오늘 날짜**로 설정 (`todayISODate()`)
- 입력란 옆에 **`2026-09-05(토)`** 표기를 추가하고, 날짜를 바꾸면 함께 갱신

**`<input type="date">` 안에는 요일을 넣을 수 없습니다.** 표시 형식을 브라우저 로캘이 정하기 때문입니다. 그래서 입력란은 그대로 두고 옆에 문구를 붙였습니다.

**저장되는 값은 `YYYY-MM-DD`를 유지합니다.** 이 형식에 의존하는 곳이 있습니다.

| 위치 | 용도 |
|---|---|
| `normalizeDateForFileName()` | 산출물 파일명의 날짜 부분 |
| `history_master.sermon_date` | 작업내역 |
| `metadata.sermon_date` | 프롬프트·temp.json·office 산출물 |

값에 `(토)`를 넣으면 이 경로들이 모두 영향을 받습니다.

`todayISODate()`는 `toISOString()`을 쓰지 않습니다. UTC 기준이라 한국 시간대에서 **하루가 어긋날 수 있기** 때문입니다. 존재하지 않는 날짜(예: `2026-02-31`)도 되돌려 확인해 걸러 냅니다.

> 참고: 설교일은 보통 **지난 주일**이라 오늘 날짜가 늘 맞지는 않습니다. 요청대로 오늘로 두었고, "가장 최근 주일"이 더 맞다면 기본값 계산만 바꾸면 됩니다.

### 3. Step1 — 기본정보 요약 표시

`AI(LLM)를 이용하여 초안 작업을 합니다.` 아래에 한 줄을 추가했습니다.

```
시리즈 있음:  본받고 싶은 교회(1) · 데살로니가서를 시작하며 · 살전 1:1-10
시리즈 없음:  데살로니가서를 시작하며 · 살전 1:1-10
제목/성구 없음: 기본정보에서 제목과 본문 성구를 먼저 입력해 주세요. (경고색)
```

값이 비면 안내로 바뀌므로, **프롬프트 생성 전에 필수값 누락을 알아챌 수 있습니다.**

### 4. Step2 — 시리즈 칸을 조건부로 표시

- **시리즈가 있을 때만** 칸을 렌더합니다
- 안내 문구 교체
  - 이전: `시리즈 설교인 경우에만 입력합니다. 비워 두면 산출물에 표시하지 않습니다.`
  - 변경: `QT 준비에서 입력한 시리즈입니다. 필요 시 수정합니다.`

이전 문구는 Step2에서 시리즈를 **새로 정하는 것처럼** 읽혔습니다. Step2는 Step1 결과를 검토·수정하는 화면이므로 다른 필드(제목·본문 성구)와 같은 어투로 맞췄습니다.

## 추가 작업 — 구분자 변경 및 사람 입력 확정 (2026-09-05)

### ⚠️ 검토 중 발견한 실제 버그 — DB에 사람 입력값이 안 들어갔다

구분자를 검토하다 더 심각한 문제를 찾았습니다.

```go
// 이전
var doc QTLLMDoc
json.Unmarshal([]byte(jsonText), &doc)
s.writeTempJSON(&doc, audience, series)   // series를 여기서만 덮어씀
...
s.saveHistory(req, jsonText)              // ← LLM 원본 문자열을 그대로 저장
```

`series` 덮어쓰기가 **메모리상 doc에만** 반영되고, DB에는 **LLM이 준 원본 문자열**이 들어갔습니다.

| 저장처 | 이전 series 값 |
|---|---|
| `temp.json` | 화면 입력값 ✓ |
| `sermon_summary.md` | 화면 입력값 ✓ |
| **작업내역 DB** | **LLM이 준 값** ✗ |

재작업은 DB에서 복원하므로, **사용자가 입력한 시리즈가 아니라 LLM이 뱉은 값으로 되살아났습니다.** 시리즈는 사람이 직접 입력하는 값이라 LLM이 정확히 echo하리라 보장할 수 없습니다.

**수정**: 사람 입력값을 `doc.Metadata`에 확정한 뒤, **그 doc을 다시 직렬화해 DB에 저장**합니다. temp.json·md·DB가 모두 같은 doc에서 나옵니다.

> 8/31 확정 사항 2의 "LLM 원본 JSON 전문 저장"에서 **"사람 입력값을 확정한 JSON 전문 저장"으로 바뀝니다.** `sections`·`infographic`·나머지 metadata는 파싱→직렬화를 거쳐도 그대로 보존되므로 손실은 없습니다.

### 구분자 변경 — `' — '` → `'|||'`

| 항목 | 내용 |
|---|---|
| 이전 | `" — "` (em dash) |
| 변경 | `"\|\|\|"` |

`—`와 `-`는 **제목 안에 실제로 등장할 수 있습니다**(`사랑 — 가장 큰 계명`). 지금은 라벨을 split하지 않아 무해했지만, 폴백 경로에서 되나누게 되면서 안전한 구분자가 필요해졌습니다.

- `splitHistoryTitle()` 신설 — 구분자가 없으면 전체가 제목(시리즈 없음 / 도입 이전 이력)
- `sanitizeSeriesTitlePart()` — 입력값에 구분자가 섞이면 제거
- `master.Title` 폴백 2곳([history_service.go:499](../../service/history_service.go#L499), [:620](../../service/history_service.go#L620))을 되나누기 기반으로 교체

### 제목도 사람 입력 기준 — 단, 장년만

| 연령대 | 제목 |
|---|---|
| **장년** | **화면 입력값으로 확정** (`ensureQTTitlePrefix` 적용) |
| 청년·중고등·어린이 | **LLM이 연령대에 맞게 지은 제목 유지** |

비장년은 프롬프트가 연령대에 맞는 제목을 새로 짓게 하고 있어, 화면 입력값으로 덮으면 그 기능이 무의미해집니다. Step2의 `resolveQtTitleByAudience`가 이미 쓰던 규칙을 **Step1로 앞당겨 확정**했습니다.

작업내역 목록 라벨의 제목도 `doc.Metadata`의 확정값을 씁니다. **목록에 보이는 제목과 실제 산출물 제목이 어긋나지 않습니다.**

### 목록 표시 — 시리즈를 분리해 렌더

`|||`가 목록에 그대로 보이면 안 되므로 프론트에서 되나눠 표시합니다.

```
본받고 싶은 교회(1)          ← 작은 회색 글자
데살로니가서를 시작하며
```

검색(`title LIKE`)과 정렬은 영향 없습니다. 구분자가 검색어에 들어가지 않고, 시리즈명이 앞에 있어 묶음 정렬도 유지됩니다.
