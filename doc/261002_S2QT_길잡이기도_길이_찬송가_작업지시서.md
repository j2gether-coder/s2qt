## 단계 A — 길이 (장년만)

[prompt_qt_json.go:478](../service/prompt_qt_json.go#L478) · [:492](../service/prompt_qt_json.go#L492)

```
Summary: 3-4 sentences, about 150-180 Korean characters (모두 한글)
- 경건하고 사려 깊게. 본문의 상황과 오늘의 의미를 담는다.
- 길게 늘여 글자 수를 채우지 않는다. 문장 수와 글자 수를 모두 지킨다.
- Example: "여호사밧은 압도적인 적군을 앞두고도 자신을 바라보지 않았습니다."
```

```
Prayer: 3-4 sentences, about 120-150 Korean characters (한글만)
- Tone: Serious, humble, warm
- Structure: 경배 → 회개 → 감사 → 간구
  네 단계를 모두 담되 압축한다. 문장 수를 줄이려고 단계를 빼지 않는다.
  한 문장이 두 단계를 겸해도 좋다.
- Example: "주님, 나의 생각을 말씀으로 지켜주세요..."
```

> **문장 수와 글자 수를 함께 적습니다.** 문장 수만 적으면 모델이 한 문장을 길게 늘여
> 결과가 그대로이고, 글자 수만 적으면 문장이 토막 납니다.
>
> **기도의 "압축하되 빼지 말 것"이 핵심입니다.** 5~6문장을 3~4문장으로 줄이라고만 하면
> 모델은 **회개나 감사를 통째로 버립니다.** 가장 먼저 사라지는 것은 회개입니다.

## 단계 B — 찬송가 프롬프트 4곳

### B-1 JSON 스키마 템플릿 ([:197](../service/prompt_qt_json.go#L197)) — **가장 중요**

```go
"hymn": "{{hymn}}",
```

지금은 `"새찬송가 456장"`이라는 **하드코딩된 값**입니다. series·bible_text·preacher 등
입력에 묶인 다른 필드는 모두 자리표시자인데 hymn만 구체적인 값이라, 모델이 그대로 베낍니다.

> **입력이 비면 `"hymn": ""`로 치환됩니다.** 그래서 B-2의 조건부 규칙이 반드시 함께 가야
> 합니다. 아니면 추천 기능이 죽습니다.

### B-2 METADATA FIDELITY ([:156-167](../service/prompt_qt_json.go#L156))

hymn은 **조건부**라 기존 목록에 그냥 넣으면 안 됩니다(나머지는 "절대 지어내지 말 것").
목록 아래에 예외 문단으로 둡니다.

```
hymn 은 조건부다.
  입력값이 있으면  → 글자 그대로 복사한다. 다른 찬송가로 바꾸지 않는다.
  입력값이 비어 있으면 → 본문에 어울리는 한국 찬송가 1개를 추천한다.
                        확신이 없으면 "-" 로 둔다.

  입력 hymn = "새찬송가 488장"  일 때
    ✓ "hymn": "새찬송가 488장"
    ✗ "hymn": "새찬송가 456장"     ← 다른 곡으로 바꿈. 금지
```

### B-3 필드 규칙 ([:143-144](../service/prompt_qt_json.go#L143))

한 줄에 두 지시가 섞여 있습니다. 치환되면 *"Use 새찬송가 488장 if provided; recommend 1
Korean hymn if empty"* 가 되어 모순처럼 읽힙니다. B-2를 가리키게 줄입니다.

```
- hymn: 아래 METADATA FIDELITY 의 hymn 규칙을 따른다
```

### B-4 기본 프롬프트 예시 ([:60-64](../service/prompt_qt_json.go#L60))

`Example: "새찬송가 324장"`은 **형식** 예시로만 남기고, 값을 베끼지 말라는 말을 붙입니다.

```
metadata.hymn:
  한국 찬송가 표기 형식. 값 자체는 입력값을 따른다(METADATA FIDELITY 참조).
  형식 예: "새찬송가 324장"
  ❌ Wrong: "Hymn 456" or "Love Song (사랑의 노래)"
```

## 단계 C — 찬송가 코드 확정

[qtstep1_service.go](../service/qtstep1_service.go) `Save()`의 시리즈·제목 확정 바로 아래.

```go
// 찬송가는 조건부다. 화면에 입력이 있으면 사람 값이 이기고,
// 비어 있으면 LLM이 추천한 곡을 살린다.
hymn := normalizeHymnText(req.Hymn)
if hymn != "" {
    doc.Metadata["hymn"] = hymn
}
```

**C-2 `saveHistory`의 값도 맞춰야 합니다.** 지금은 `strings.TrimSpace(req.Hymn)`이라,
`normalizeHymnText`가 접두어("찬송가:")를 떼면 **DB와 temp.json이 갈립니다.**
`Save()`에서 한 번 계산한 `hymn`을 `saveHistory`까지 넘기십시오.

> 지금 코드는 `history_master.hymn`에 **화면값**, `temp.json`에 **LLM값**을 넣고 있습니다.
> 목록에 보이는 찬송과 주보에 찍히는 찬송이 다를 수 있었습니다. 9/5 시리즈 버그와 같은 모양입니다.

**재작업은 손댈 것이 없습니다** — 확정된 값이 DB의 JSON에 들어가므로 자동으로 따라옵니다.

## 함정

1. **B-1만 하고 B-2를 빠뜨리면 추천 기능이 죽습니다.** 입력이 비면 스키마가 `"hymn": ""`로
   치환되어, 모델이 빈 값을 그대로 복사합니다.
2. **C-2를 빠뜨리면** `normalizeHymnText`가 접두어를 떼는 경우에만 DB와 temp.json이 갈립니다.
   접두어 없는 입력에서는 드러나지 않아 **눈치채기 어렵습니다.**
3. **비장년 길이를 함께 고치지 마십시오**(확정 4). md는 장년 전용이고, 다른 연령대는
   각자 이유가 있는 길이입니다.
4. **기도에서 "4단계 유지"를 빼면 회개가 먼저 사라집니다.** 문장 수만 줄이라는 지시는
   구조를 보호하지 않습니다.
5. 저장소 전체가 CRLF입니다. **`gofmt -w` 일괄 실행 금지.**
