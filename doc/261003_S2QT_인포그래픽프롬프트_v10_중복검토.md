# 261003 · 인포그래픽 프롬프트 v10 중복 검토

> 대상: [261003_QT_인포그래픽_생성_프롬프트_v10.md](261003_QT_인포그래픽_생성_프롬프트_v10.md) (22.3KB, 661줄)
> **READ ONLY 검토서**입니다. v10을 수정하지 않았습니다.

## 결론 먼저

**중복은 대부분 의도된 것이고 그대로 두는 편이 낫습니다.** 프롬프트에서 핵심 규칙의 반복은
준수율을 올립니다. 줄여서 얻을 토큰보다 잃을 통제력이 큽니다.

**대신 중복보다 중요한 것을 찾았습니다 — 실제 `sermon_summary.md`와 어긋나는 곳이 3건 있습니다.**
v10이 전제하는 입력 형식이 10-01 이후 바뀐 산출물과 맞지 않습니다.

## 1. 불일치 — 이쪽이 먼저입니다

### 1-1. `오늘의 적용` → 실제 md는 `깊은 묵상과 적용` ★

10-01 작업에서 md의 섹션 제목을 바꿨습니다. 내용이 QT reflection(`…생각해봅시다`)이 되었기
때문입니다([10-01 작업로그](_working/261001_작업로그_결과.md)).

```markdown
## 깊은 묵상과 적용          ← 실제 md (10-03 산출물로 확인)
- 내가 과거에 받은 큰 은혜를 기억하며 이웃을 배척하지 않고 있는지 생각해봅시다.
```

v10은 `오늘의 적용`이라고 **10곳**에서 부릅니다 — 112, 405, 407, 411, 421, 425, 443, 587, 611, 617.

특히 411줄이 문제입니다.

> `오늘의 적용` 섹션 제목은 항상 유지한다.

입력 md에 그 제목이 없으므로, 이미지 LLM은 **제목을 바꿔 쓰거나**(원문 훼손) **혼동**합니다.

> **다행히 §11의 나머지 규칙은 그대로 맞습니다.** "질문 문장 자체가 중심 내용", "키워드+설명으로
> 바꾸지 말 것"은 `…생각해봅시다` 형식과 정확히 들어맞습니다. **제목만 바꾸면 됩니다.**

### 1-2. `말씀을 따라` 3개인 경우가 빠져 있습니다

| | 규칙 |
|---|---|
| 앱 프롬프트 | `follow : 3~5개` ([prompt_qt_json.go](../service/prompt_qt_json.go)) |
| 검증 | `infographicFollowMin = 3` ([infographic_service.go](../service/infographic_service.go)) |
| **v10 §8-1** | **4개 또는 5개** |

**3개짜리 md가 정상적으로 생성될 수 있는데 v10에 레이아웃 규칙이 없습니다.** §8-3(4개 → 1단 4열),
§8-4(5개 → 1단 5열)만 있습니다.

### 1-3. `더하는 말씀` 0개인 경우가 빠져 있습니다

앱은 `extra : 0~3개`이고, **0개면 md에서 섹션 자체가 사라집니다**
(`writeInfographicParagraphs`가 비면 아무것도 쓰지 않음).

v10 §9-1은 **1개·2개·3개**만 다룹니다. 섹션이 아예 없는 md를 받으면 규칙이 없습니다.

> 같은 구조로 **관련 성구 0개**(§13)는 "없는 경우"가 제대로 들어 있습니다. 대비됩니다.

#### B의 상세 — §20과 §21

```
§20 생성 전 구성안          §21 최종 텍스트 검수
  제목                        시리즈명
  시리즈명 유무                제목
  성경본문                     성경본문
  말씀의 길잡이                말씀의 길잡이
  말씀을 따라(항목 수·내용)      말씀을 따라 각 항목과 짧은 제목
  더하는 말씀(사례 수·구조)      더하는 말씀의 제목과 설명
  말씀의 핵심                  말씀의 핵심
  오늘의 적용                  오늘의 적용 질문
  오늘의 기도                  오늘의 기도
  관련 성구 또는 한 줄 메시지     관련 성구 / 한 줄 메시지
  대표 일러스트 콘셉트           AI 안내문
  전체 레이아웃
  하단 AI 안내 영역
```

**§20은 "구성안에 담을 것", §21은 "틀리지 않았는지 확인할 것"으로 목적은 다릅니다.**
다만 목록이 같아 LLM이 §21을 §20의 재탕으로 읽을 수 있습니다.

→ §21을 목록이 아니라 **§20에서 특히 틀리기 쉬운 것**으로 좁히는 편이 낫습니다.
   실제로 617줄("특히 `오늘의 적용`에 키워드가 들어가지 않았는지")이 §21의 진짜 값어치입니다.
